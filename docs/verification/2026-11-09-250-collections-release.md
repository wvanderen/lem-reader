# Verify and release Collections: verification and release record (issue #250)

Scope: the release gate for Collections after the feature slices (#242 base
surface, #243 order/removal editing, #244 chapter assignments, #245
referenced-work deletion, #246 shared completion, #247 continue/next, #248
backup round-trip, #249 import conflicts). This record gathers the
deterministic, three-engine, and reference-environment evidence that the
shipped slices together satisfy the release acceptance in
`docs/specs/collections-and-long-works.md` §9 ("Collection delivery") and the
issue's compatibility contract. No deferred scheduling/sharing feature ships
here; no coverage was narrowed and no threshold was relaxed.

Implementation on this branch: one new deterministic cell —
`tests/e2e/collections/collections.spec.ts` "release gate: pointer create +
rename, keyboard remove + delete — the input-method matrix closes (REL-250)".
Everything else is evidence gathered by running the existing shipped suites;
the product tree is byte-identical to main throughout the branch.

## Linux-WebKit container-lane observations (recorded honestly, never excluded)

The local container lane (Linux GTK WebKit, version-matched Playwright image
per #253) fails 7 collections-family cells that are green on host Chromium,
host Firefox, and macOS WebKit (the #249 PR gate ran this exact product tree
green on all three macOS engines at 1045763; the commits since are
docs-only). Blame was established per the #241 precedent: a clean
`origin/main` worktree (33ab3f7, no branch changes) in the same container
lane reproduces the failures, while the same cells pass in the same
container under **chromium** — the divergence is the Linux WebKit engine,
not the container environment and not this branch. Two signatures:

1. **Hash-only goto after reload is swallowed (6 cells).** Cells that seed
   raw rows via `page.evaluate`, call `page.reload()`, then
   `page.goto(…#/article/…)` land on the Library route — the fragment
   navigation never routes (the failure snapshot still shows "Saved
   articles"). GTK WebKit drops the same-document navigation issued while
   the reloaded document is still settling. Inserting a settle assertion
   between reload and goto (the DISC-244-02 shape, which passes) makes the
   route land.
2. **End-key navigation leap credits chapter ends (DISC-246-08, revealed by
   that settle probe).** With the route landed, the cell's End-key leap is
   credited as traversal on this engine: `ArticleView`'s scrolling capture
   suppresses programmatic scrolls for a 250 ms window after the End/Home
   keydown (`ArticleView.tsx`, "End/Home are NAVIGATION keys"), and GTK
   WebKit's animated jump emits classified scroll events after that window,
   so the leap's stream registers as reading moves. Chromium, Firefox, and
   macOS WebKit finish (or coalesce) the leap inside the window.

Classification pending the PR gate's macOS WebKit result (recorded below):
if macOS WebKit passes these cells, both signatures are the fourth and
fifth registered Linux-WebKit lane divergences (after
`page-turn-focus-handoff` and the footnotes continuation cell); the
container lane stays a dev-box convenience, and macOS reference truth owns
WebKit. If macOS also fails, the End-key signature would be a genuine
skipped-chapter honesty defect to fix before release — the gate result below
settles which world this record describes.

## Disclosed limits

- The reference-work extraction limit ("1 part of the original could not be
  displayed") is the long-work record's (#241) finding and is unchanged by
  Collections; Collections reference works and chapters, never extraction.
- Linux-WebKit container-lane divergences above; macOS reference truth via
  the PR gate (and, exhaustively, the dispatched evidence run).
- Out of scope by contract and absent from the tree: calendars/deadlines/
  reminders, recurring sessions, arbitrary passage or generated-part entry
  targets, nested collections, duplicate identical targets, separate reread
  attempts or plan-specific completion histories, reading-time estimates,
  public sharing/collaboration, collection-only export, manual chapter-bound
  editing, whole-work page totals.
