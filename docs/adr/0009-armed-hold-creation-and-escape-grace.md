# Highlights create on release and undo by an Escape grace

Field feedback on the slot rounds found the creation flow clunky: the floating toolbar lingered after every creation and needed a click elsewhere to dismiss; the digit-hold gesture created only if the digit was still physically down at mouse-up (a release-order race that read as "does not save on mouse release"); nothing showed the slot's color until after the release; and the toolbar mounted mid-drag, blocking the text being selected and jumping with every selectionchange. The decision: the digit hold IS the automatic creation path — plain selections never create (selecting to copy or to keep your place stays free of side effects; a preferences toggle for create-on-every-release was considered and deferred), and the hold becomes a marker pen. A digit pressed at any point during a pointer gesture arms that slot (Escape mid-drag still cancels; a new gesture re-arms); the digit/pointer release order no longer matters; while armed, the native selection itself is tinted with the slot's derived color (`::selection` on the reading root — no overlay marks, no layout), so the sweep paints in the chosen color immediately and the mark's arrival on release is visually seamless. Every creation path (gesture, toolbar slot pill, H, N) then dismisses the toolbar immediately and announces "Highlight saved. Press Escape to undo." politely — undo moves to a grace window: for ~4 seconds after a creation, Escape deletes the just-created, UNEDITED highlight; any edit to it, any open dialog, or a newer creation retires the grace, and it survives scrolling, resizing, and new selections. The saved-state toolbar variant ("Highlighted / Undo / Add note") is gone entirely. Escape is a ladder, never a surprise: the open dialog always wins first (dismiss + save), then the undo grace, then the fresh-selection toolbar (dismiss + collapse the selection — its first explicit keyboard dismissal), then an armed hold (cancel). The toolbar itself mounts only on pointer-up, never mid-drag (keyboard selections show it immediately). No Enter-commits binding exists: nothing lingers after creation, so the grace needs no dismissal — Enter keeps meaning "activate the focused element" everywhere. The hold gesture stays pointer-scoped; keyboard and touch readers reach every outcome through the toolbar's slot row, H, and N — parity by other means, not a privileged path.
