<objective>
Fix web-article image import — four repro-confirmed gaps that make images "only work for epubs":

1. The image profile's content-type gate at safeFetch.ts L236 is a hard pre-read refusal even though the comments (safeFetch.ts L230-234, fetchImageAsset.ts L74-78) call it advisory. CDNs/S3/signed URLs serving application/octet-stream, binary/octet-stream, or an empty content-type throw "unsupported-content-type" BEFORE the authoritative magic-byte sniff (D20-10) ever runs.
2. safeFetch.ts L199 sends only User-Agent. Hotlink-protected CDNs (common on news sites) return 403 on image fetches → typed "fetch" refusal → placeholder.
3. extractInline (htmlToBlocks.ts L121-156) has no img arm — a paragraph's inline imgs are silently dropped (violates the Honesty constraint).
4. figureBlock (htmlToBlocks.ts L210-249) reads only src; srcset is also STRIPPED by DOMPurify (not in ALLOWED_ATTR, L84), so srcset pages import the tiny placeholder src.

Purpose: web articles import their real images through the SAME one-pipeline SSRF substrate (D20-12) with document-profile byte-stability preserved.
Output: patched server modules + extended unit specs; no schema change, no e2e change.
</objective>
