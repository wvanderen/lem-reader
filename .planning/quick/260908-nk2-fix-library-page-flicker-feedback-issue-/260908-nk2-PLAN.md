# Fix library page flicker — feedback aside flashes during load

## Problem

On the library route (`#/`), LibraryView mounts with `status: "loading"` and empty `items` (LibraryView.tsx L216-217). While loading, the page is short — header row, switcher, search, tag filter, empty `ul`, the "Opening article…" status region, and the `.project-feedback` aside — so the aside sits inside the viewport. When the async `Promise.all` load (L410-441) resolves, rows render, the page grows, and the aside is pushed below the fold. The reader sees the "Share feedback on GitHub" issue link flash on screen, then vanish. This violates the project's calm, no-flash-of-wrong-content UX value.

## Fix

Gate the aside's mount on the settled load: render it only when `status !== "loading"`. The aside's markup stays byte-identical — only its mount timing changes.

Two facts make this gate safe and terminal (verified in source):

1. The load effect (L401-450) transitions status only `loading → ready` or `loading → error`; a `refreshKey` re-run (after remove/add/edit) never returns status to `"loading"`, so the aside stays mounted across refreshes — no new flicker on re-loads.
2. The gate renders the aside in the `"error"` state too — a failed load still gets the feedback link (the error page is exactly where a reader may want to file an issue).
