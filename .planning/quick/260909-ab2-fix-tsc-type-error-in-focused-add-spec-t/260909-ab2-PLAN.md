# Fix tsc type error in focused-add.spec.ts breaking the Vercel prod build

## Problem

The production deploy fails on `npm run build` (Vercel, Node 22.22.3). The build script is
`build:api && tsc && vite build`; the `tsc` step fails:

```
tests/e2e/library/focused-add.spec.ts(377,77): error TS2339: Property 'title' does not exist on type
'{ id: string; revision: number; lang: string; provenance: { sourceUrl?: string ...; title: string; ... }; ... }'.
```

Commit 109fb3d ("feat(library): compact article cards and add read status actions") introduced
the close-then-navigate e2e case, whose h1 assertion reads `fixtureArticle.title`. Fixtures are
`CanonicalArticle`s — the title lives at `provenance.title`, the accessor used by every other
spec (40+ references across the e2e and unit suites). The commit shipped without a `tsc` pass,
so the type error slipped through and broke prod.

## Fix

One-line, spec-side only: `fixtureArticle.title` → `fixtureArticle.provenance.title` at
focused-add.spec.ts L377. No production code changes; the runtime value is identical (the
assertion was type-wrong, not behavior-wrong — the case passed in Playwright runs because
`tsc` isn't part of the e2e path).
