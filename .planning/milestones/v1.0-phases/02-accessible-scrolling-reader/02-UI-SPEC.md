# Phase 2 — UI Design Contract

> Visual and interaction contract for the Accessible Scrolling Reader phase.
> Generated by gsd-ui-researcher; to be verified by gsd-ui-checker.
> **Extends** `01-UI-SPEC.md` (read first). This phase reuses Phase 1's spacing
> scale, type scale, color tokens, copywriting rules, and interaction baselines
> verbatim; new surfaces (header, settings panel, progress hairline, resume
> banner, storage-failure banner) are specified here and MUST stay consistent
> with the calm/booklike foundation.

---

## Phase Scope

Phase 2 turns Phase 1's static foundation into a calm, adaptable, resumable
reader. It introduces the app's first persistent chrome and the first
user-mutable visual layer. It does **not** ship pagination, measurement/trust
pipeline, or annotations.

**In scope (Phase 2):**
1. A slim, quiet **persistent top header** across both existing views
   (FixtureList, ArticleView) hosting the settings gear (D2-02).
2. A **slide-over Reading Settings panel** (D2-01) with live-applied typography
   (family, size, measure, spacing preset) and theme controls, debounced
   persistence, and a Reset-to-defaults affordance.
3. **Theme set** — Sepia (warm-paper default), Light, Dark — as CSS custom
   properties switched via `[data-theme="..."]` on `<html>` (D2-09).
4. **Typography control model** — hybrid: 3 spacing presets + stepped size and
   measure fine-tunes (D2-05, D2-07, D2-08).
5. **Location restore** — silent scroll to saved grapheme offset + dismissible
   "You left off here" resume banner (D2-10); debounced scroll-save + flush on
   hide (D2-11).
6. **Quiet structural progress** — 2px scroll-progress hairline under the header
   + a screen-reader live region announcing heading changes (D2-12). No page
   numbers, no prominent percentage bar.
7. **Recoverable local-state error** — dismissible storage-failure `.status`
   banner + an explicit, focus-trapped "Reset local data?" confirmation for
   corrupt/unupgradeable storage (D2-13, STATE-05).
8. Persistence layer (Dexie `version(2)`) populating the reserved
   `settings`/`location` slots, Zod-validated on read and write (STATE-04).

**Out of scope (deferred):**
- Responsive pagination, page-turn controls, dual-mode navigation, oversize
  diagnostics — **Phase 4** (PAGE-01…05, PAGE-09).
- Layout measurement, `document.fonts.ready` invalidation pipeline, stale-result
  cancellation, Pretext calibration — **Phase 3** (PAGE-06…08). Phase 2's
  typography changes reflow the scrolling view directly; it does NOT own the
  measurement/trust pipeline.
- The true OpenDyslexic web font — **Phase 3** (decided this phase: system-stack
  approximation only; see Typography). Phase 3 may introduce `document.fonts.ready`
  handling if it promotes a real web font.
- Highlights and notes — **Phase 5** (ANNO-01…07, STATE-03).
- Heading navigator and line-focus aid — **v2** (ORNT-01/02).

**Locked by STACK.md / AGENTS.md (do not revisit):**
- Authored CSS layers + CSS custom properties (NO Tailwind, NO component suite,
  NO shadcn).
- Semantic HTML as the renderer; DOM reading order equals document order.
- React 19 + TypeScript + Vite 8 SPA; React state/context only (no
  Redux/Zustand).
- Hash-based routing (Phase 1, D2 confirms settings is a **panel**, not a route).
- Zod-at-boundary validation for every persisted record.

**Locked by Phase 1 UI-SPEC (carried forward unchanged):**
- Spacing scale (multiples of 4) and the 44px `--touch` minimum.
- Type scale: exactly 4 sizes (14 / 18 / 22 / 32px), 2 weights (400 / 600).
- Body serif / UI sans / code mono font stacks.
- Warm-paper color tokens + accent reserved-for list + contrast contract.
- Copywriting microcopy rules (sentences not fragments; direct second person;
  never blame the reader; never leak jargon — "article" not "fixture").
- Interaction baselines: visible focus (2px outline + 2px offset), reduced-motion
  gate, forced-colors gate, programmatic status pattern, always-underlined links.
- Layout breakpoints and the invariant calm reading measure.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (authored CSS layers per STACK.md; shadcn/component suites forbidden) |
| Preset | not applicable |
| Component library | none — semantic native HTML elements only (`<dialog>`, `<button>`, `<input type="radio">`, `<details>`, `<header>`, `<main>`, `<article>`) |
| Icon library | none. The gear, dismiss (×), and progress markers are inline SVG (no library). All icons MUST carry an accessible name via `aria-label` or visually-hidden text and MUST be `aria-hidden` when decorative. |
| Font | System stacks only (no web fonts this phase). See Typography. |

**Settings application path (D2 agent's discretion, locked here):** preferences
resolve to a `data-theme="..."` attribute on `<html>` (theme) plus CSS custom
properties on `:root` (family/size/measure/spacing) written by a React context.
This honors the authored-CSS/no-Tailwind constraint and lets the live-apply
preview (D2-03) re-render the article behind the panel with one token swap.

## Spacing Scale

Carried forward verbatim from Phase 1. All spacing MUST round to a token here.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap, hairline offset, dense inline padding |
| sm | 8px | Compact control spacing, banner internal padding, header vertical inset |
| md | 16px | Default element spacing, panel section gaps, banner copy rhythm |
| lg | 24px | Section padding inside the settings panel, header horizontal padding |
| xl | 32px | Layout gaps, panel outer margin on wide viewports |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level top/bottom padding of reading view |
| touch | 44px | Minimum interactive hit area — gear, reset, resume/top, ×, theme/size/measure/preset controls, wipe confirmation actions |

**Exceptions (override the scale where stated):**
- **Touch target minimum: 44 × 44 px** (`--touch`) for EVERY interactive control
  added this phase. Native form controls (`<input type="radio">`) MUST have their
  hit area extended to 44px via padding/labeled-by area, not rely on the native
  ~13px radio glyph (A11Y-01, A11Y-07).
- **Focus ring: 2px solid `--focus-ring` outline + 2px offset** (Phase 1 baseline;
  applies to all new controls).
- **Header height: 48px** (not a spacing token; see Component Inventory).
- **Progress hairline: 2px** tall (see Component Inventory).
- **Reading measure: typographic `ch` units**, not px (52/58/64/72ch; see
  Typography). Calm measure stays invariant per breakpoint unless the reader
  widens it.

## Typography

Phase 1's type scale and font stacks are the **defaults** and remain in force
for every surface. Phase 2 makes four of the defaults user-mutual and adds no
new role.

**Font stacks (system-only — no web fonts this phase):**

| Role | Stack | Mutability |
|------|-------|------------|
| Body — serif (D-07 default) | `'Iowan Old Style', 'Source Serif Pro', 'Source Serif 4', Georgia, Charter, 'Times New Roman', serif` | User-selectable |
| Body — sans | `system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif` | User-selectable |
| Body — dyslexia-friendly (D2-06, Option A) | `Verdana, Tahoma, 'Segoe UI', Geneva, sans-serif` | User-selectable. Font-load-safe; no `document.fonts.ready` gate required in Phase 2. |
| UI chrome (header, panel labels, banner copy, status) | `system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif` | Fixed (Phase 1) |
| Code / preformatted | `ui-monospace, 'SF Mono', SFMono-Regular, Menlo, Consolas, 'Liberation Mono', monospace` | Fixed (Phase 1) |

> **OpenDyslexic is deferred to Phase 3.** If a real web font is introduced
> later, Phase 3 owns the `document.fonts.ready` gate and the live-apply
> preview must not flash unstyled prose.

**Type scale (unchanged from Phase 1 — exactly 4 sizes, 2 weights):**

| Role | Size | Weight | Line Height | Stack |
|------|------|--------|-------------|-------|
| Body | 18px *(default; user-steppable, see below)* | 400 (regular) | preset-driven *(see below)* | selected body stack |
| Meta / Label | 14px | 400 (regular) | 1.45 | UI sans |
| Subheading (h2, h3, h4) | 22px | 600 (semibold) | 1.3 | selected body stack |
| Display (article title h1) | 32px | 600 (semibold) | 1.2 | selected body stack |

**Relative-unit rule (hierarchy invariant — Dimension 4):** the px values above
are the **defaults at the default body step (18px)**. Subheading and Display
sizes MUST be expressed as **relative `em` units derived from the resolved body
size** (Subheading ≈ `1.22em`, Display ≈ `1.78em`), NOT as fixed px. This keeps
the type hierarchy from inverting when a user picks a large body step (22 or
24px): headings always stay proportionally larger than body. Only Body and
Meta/Label are sized in px (Body is the user-controlled knob; Meta/Label is the
fixed chrome size). The locked type-scale *relationships* above are preserved;
this rule only clarifies that headings move in `em`, matching Phase 1's existing
`em`-based block rhythm.

**Typography control model (D2-05, D2-07, D2-08) — hybrid:**

*Spacing presets* own line-height + letter/word-spacing (set together); *size*
and *reading measure* are independent stepped fine-tunes layered on top of any
preset.

**Spacing presets (D2-08 — preset-internal only, not individually adjustable):**

| Preset | line-height | letter-spacing | word-spacing |
|--------|-------------|----------------|--------------|
| Compact | 1.4 | 0 | 0 |
| **Comfortable** *(default = D-07 baseline)* | 1.6 | 0 | 0 |
| Spacious | 1.8 | 0.01em | 0.05em |

**Size steps (D2-07, stepped/discrete — arrow-key navigable):**

`16px`, `18px` *(default)*, `20px`, `22px`, `24px` — applied to body text;
headings scale relatively so calm rhythm is preserved (Phase 1 already uses `em`
for block rhythm).

**Reading-measure steps (D2-07, stepped/discrete):**

`52ch`, `58ch`, `64ch` *(default = D-07)*, `72ch` — applied to `.article-body`
`max-width`.

**Block rhythm:** unchanged from Phase 1 (paragraph `margin-block: 1em 1em`;
`h2` `1.5em 0.5em`; `h3`/`h4` `1.25em 0.5em`; etc.). `em`-based rhythm MUST be
preserved so size changes stay calm.

**Live-apply (D2-03):** each control writes through to `:root` custom properties
immediately; the article behind the panel reflects the change in context.
Persistence is **debounced** (planner picks the window). There is **no Save /
Commit step**.

**Reset (D2-04):** a single **Reset to defaults** affordance restores the D-07
warm-paper baseline — serif body stack, 18px, 1.6 line-height, Comfortable
preset, 64ch measure, Sepia theme. The persisted default set IS the warm-paper
tokens, not "unset."

### Role usage (60/30/10)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surface` | App background, article-view background, header background, settings panel scrim |
| Secondary (30%) | `--surface-raised` | Settings panel surface, resume banner, storage-failure `.status` banner, wipe-confirmation surface, code blocks, figures (unchanged) |
| Accent (10%) | `--accent` | See reserved-for list below |
| Destructive | `--destructive` | "Reset local data" destructive action border + the warning icon in storage-failure banner only |

**Accent reserved for (explicit list — never "all interactive elements"):**
1. Hyperlinks inside the article body.
2. The original-source URL link in the provenance block.
3. The "Open article" CTA on each fixture-list row (Phase 1).
4. The collapsed-state marker on each unsupported-content disclosure (Phase 1).
5. `:focus-visible` outline on every focusable element.
6. **Phase 2 additions:** the **progress-hairline fill** (D2-12), the **gear
   icon** when the panel is open (active affordance only — closed-state gear uses
   `--ink-soft` to stay quiet), and the **selected-state indicator** on the
   active theme / preset / size / measure option (a small filled marker or
   ring — never the whole control background).

Accent MUST NOT be used for: body text, headings, chrome backgrounds, dividers,
captions, panel section headings, banner body copy, decorative elements, or the
closed-state gear icon.

### Contrast contract (checker validates, every theme)

- `--ink` on `--surface`: ≥ 4.5:1 (body text).
- `--ink` on `--surface-raised`: ≥ 4.5:1.
- `--ink-soft` on `--surface`: ≥ 4.5:1.
- `--accent` on `--surface` and on `--surface-raised`: ≥ 4.5:1 (links count as
  body text).
- `--focus-ring` against any surface it appears on: ≥ 3:1 (WCAG 2.2 SC 1.4.11).
- `--destructive` text on its surface, if used for text: ≥ 4.5:1; otherwise it is
  border/icon-only.
- Forced-colors mode (`@media (forced-colors: active)`, already global in
  `app.css`) MUST NOT remove: link underlines, focus outlines, the disclosure
  marker, the selected-option indicator, or the gear's open/closed distinction
  (which must also be conveyed by `aria-expanded` and an icon glyph change).

**Microcopy notes specific to Phase 2:**
- "Reading settings" is the consistent noun across gear label, panel title, and
  any polite status. Never "preferences," "options," or "controls."
- The resume banner is a polite tap on the shoulder, not a modal: copy is short,
  non-alarming, and gives the reader agency without forcing a scroll decision.
- The storage-failure copy never says "database," "IndexedDB," or "corrupt."
  User-facing word is "local storage" / "reading history and saved settings."
- The wipe confirmation names the consequence ("can't be undone") and the
  recovery ("start fresh") in plain language.

## Interaction Patterns

Phase 1's interaction baselines (visible focus, reduced-motion, forced-colors,
programmatic status, always-underlined links, disclosure, skip link) carry
forward unchanged and apply to every new control. Phase 2 adds:

### 8. Reading Settings panel (D2-01, A11Y-01, A11Y-02, STATE-02)
- Opened by the **gear button** in the header; **slides over** the article from
  the inline end (right in LTR). A scrim covers the article; the article stays
  mounted (no duplicate content tree — A11Y-03).
- **Mechanism (D2 discretion):** native `<dialog>` (with `showModal()`) is the
  preferred mechanism for free focus-trap, Esc-dismiss, and inert backdrop. If
  the planner chooses a custom region instead, it MUST set `aria-modal="true"`,
  `role="dialog"`, `aria-labelledby` to the panel title, implement a roving
  focus trap, and manage `inert`/`aria-hidden` on the rest of the app.
- **On open:** focus moves to the panel title (or first control). The gear
  button's `aria-expanded` becomes `true`.
- **On close (Esc, scrim click, or ×):** focus returns to the **gear trigger**
  (predictable focus restoration — A11Y-02). `aria-expanded` becomes `false`.
- **Live-apply (D2-03):** every control writes through to `:root` tokens
  immediately; the article behind the scrim reflects the change. Persistence is
  debounced; there is no Save step.
- **Reduced motion:** the slide and scrim fade are disabled by the global
  `prefers-reduced-motion` gate (the panel simply appears/disappears). No
  required animation, ever (A11Y-06).
- **Keyboard:** Tab cycles within the panel in DOM order; Shift+Tab reverses;
  Esc closes. No keyboard trap leaks to the article (A11Y-01).
- **Touch/pointer parity:** every control has a ≥ 44 × 44 px hit area and is
  operable by touch (A11Y-07).

### 9. Form controls inside the panel (READ-02, A11Y-01, A11Y-07)
- **Typeface / Spacing / Theme** use `<input type="radio">` in a `<fieldset>`
  with a `<legend>` = the section heading. The whole option row (label + radio)
  is the 44px hit target. The **selected option** shows a small `--accent`
  marker; the marker is also conveyed by the radio's native checked state and by
  `aria-checked`/label position so it survives forced-colors.
- **Size** and **Reading width** use a stepped control. Preferred: a native
  `<input type="range">` with `min`/`max`/`step`/`value` and a visible numeric
  readout, OR a labeled stepper (`−`/`+`) with the current value shown. Either
  MUST be operable by arrow keys, have a 44px target, and announce the new value
  via the visible readout (and, for the range, `aria-valuenow`).
  - Size: 16/18/20/22/24px. Measure: 52/58/64/72ch.
- **Reset to defaults** is a `<button>` (type="button"); on activation it
  restores the D-07 baseline live and clears persisted overrides.

### 10. Location restore + resume banner (D2-10, STATE-01, A11Y-08)
- **On open:** the reader is **silently scrolled** to the saved grapheme offset
  (D-05 substrate, `[articleId+revision]` key). No scroll animation under
  reduced motion; otherwise a single calm scroll is acceptable (planner's call —
  the global gate disables it when the user prefers reduced motion).
- Immediately after, the **resume banner** appears (non-modal, polite) and a
  polite live region announces *"Returned to where you left off."*
- **Banner lifecycle:** it auto-dismisses on the reader's first scroll or
  pointer activity, OR on an explicit action (**Resume reading** / **Start from top** /
  ×). It does NOT block reading.
- **Resume reading** (primary) scrolls to the offset and dismisses; **Start from top**
  (secondary) scrolls to the article `<h1>` and dismisses.
- **No page numbers** are shown; this honors READ-05 ("does not treat responsive
  page number as permanent identity").

### 11. Scroll-save (D2-11, STATE-01)
- Location is saved **debounced after scroll stops** (planner picks the window,
  ~1–2s) **plus a flush on `pagehide` / `visibilitychange`-hidden** to cover
  tab-close and navigation.
- Save failures are swallowed from the reader's perspective but trigger the
  storage-failure banner (D2-13) — they never interrupt reading.

### 12. Progress hairline + section announce (D2-12, READ-05, A11Y-08)
- A **2px-tall, full-width hairline** sits fixed immediately under the header
  across the reading surface. Track = `--ink-soft` at ~20% alpha; fill =
  `--accent`. Width is driven by `transform: scaleX({progress})` with
  `transform-origin: inline-start`. **No CSS transition** on the transform (so
  the global reduced-motion gate is trivially satisfied and the hairline never
  animates).
- No prominent percentage bar; no page count. The hairline is glanceable and
  quiet.
- A separate **`role="status"` `aria-live="polite"` region** announces heading
  changes during scroll: *"Section: {heading text}."* Debounced so rapid scroll
  does not flood the live region (A11Y-08 — concise, non-repetitive).

### 13. Storage failure + reset (D2-13, STATE-04, STATE-05)
- **Storage unavailable / full / unwriteable:** reading continues uninterrupted.
  A dismissible `.status` banner (existing `role="status"`/`aria-live="polite"`
  pattern) shows the storage-failure copy. The app falls back to **in-memory
  defaults** for the session.
- **Corrupt or unupgradeable DB:** the reader is NOT silently wiped. A
  **focus-trapped confirmation dialog** ("Reset local data?") asks for explicit
  consent. Only on **Reset local data** (destructive) is local data cleared and
  the DB re-initialized; **Keep reading** keeps the reader reading with in-memory
  defaults and the banner still shown.
- Fixtures are static; article reading NEVER depends on Dexie, so a total
  storage failure cannot block opening or reading an article.

### 14. Persistent header (D2-02, READ-04)
- **~48px tall**, `--surface` background, **1px `--hairline` bottom rule**.
  Hosts only an app wordmark (inline-start) and the gear button (inline-end).
- **Quiet/neutral:** no accent fill, no toolbar styling, no shadow. The gear is
  `--ink-soft` when closed and `--accent` only when open. It must read as the
  quietest possible chrome or it violates READ-04.
- Stays present across FixtureList and ArticleView so focus has a stable home.

| Article body (unchanged) | direct children of `<article>` | `<h2>`–`<h4>`, `<p>`, lists, `<blockquote>`, `<figure>`+`<figcaption>`, `<pre><code>`, inline `<code>`, `<a>` |
| Fixture list (unchanged) | `<main id="main"><h1>` + `<ul>` | One `<li><article>` per saved article |

**Single content tree rule (A11Y-03):** the article is rendered exactly once.
When the settings panel is open, the article is NOT re-rendered or duplicated —
it stays mounted behind the scrim (or is made `inert`/`aria-hidden` by the
dialog mechanism). Screen-reader reading order equals document order in both
states.

## Layout

Phase 1's visual hierarchy and breakpoints carry forward. Phase 2 additions:

**Header + hairline stacking (top of viewport):**
1. `header.app-header` — ~48px, sticky/fixed top, full width.
2. `div.progress-hairline` — 2px, immediately under the header, only visible on
   the ArticleView (hidden on the FixtureList, where there is no scroll progress
   to show).
3. `<main id="main">` — Phase 1 inset (`padding-inline: md`, `padding-block: 3xl`)
   begins below the hairline.

**Settings panel geometry:**
- Slides over from the inline end. On viewports **≥ 640px**, the panel occupies
  a calm ~360–420px column; the scrim covers the rest. On **< 640px**, the panel
  is a near-full-width sheet (a small inline margin remains so the scrim is
  visible and dismiss-by-click is discoverable).
- The panel's internal sections use `gap: lg`; section rows use `gap: md`; the
  panel's outer padding is `lg`.

**Resume / storage banners:**
- Inline within `<main>`, near the top of the article (resume) or top of the
  view (storage). They are NOT fixed/sticky (sticky chrome would compete with
  content — READ-04). They sit on `--surface-raised` with a `--hairline` border,
  4px radius, `padding: lg`.

**Reflow (A11Y-04):** at 320 CSS px equivalent and 200% browser zoom, the
header, gear, panel, banners, and all form controls MUST remain visible,
operable, and within a single column with no horizontal scroll of the article
body. The measure cap (`max-width`) prevents the body from overflowing; panel
and banners fill the available width minus `md` insets.

| Breakpoint | Behavior |
|-----------|----------|
| `< 640px` | Single column everywhere. Header full width; panel = near-full-width sheet; banners full width (minus `md` insets). Article body fills width with `padding-inline: md`. |
| `640–1024px` | Article body capped at the reader's chosen measure (`max-width` in `ch`), `margin-inline: auto`. Panel ~360–420px column over scrim. Fixture list two columns (Phase 1). |
| `≥ 1024px` | Same measure cap — the reading column does NOT widen with viewport (calm measure is invariant). Fixture list max three columns (Phase 1). |
