## Phase Goal

**As a** reader, **I want to** read and resume articles in a calm scrolling view with adaptable typography, theme, and recoverable local preferences, **so that** the reading experience matches my access needs and I never lose my place.

> Plan 02 layers **persistence + STATE-05 recovery** onto the in-memory settings slice from Plan 01. The reader's choices now survive reload, and any storage failure is graceful and non-blocking.

<objective>
Make the reader's typography/theme preferences persist in Dexie `version(2)` as one composite Zod-validated record keyed `"reader-prefs"`, with debounced writes (~400ms) and a dual-event flush (`visibilitychange`-hidden + `pagehide` — never `beforeunload`). Implement STATE-05 graceful recovery: storage unavailable/full → dismissible banner + in-memory defaults (reading never blocked); corrupt/unupgradeable DB → a focus-trapped "Reset local data?" confirmation where `db.delete()` runs ONLY in the destructive button handler (Pitfall 8 — never in a catch block).

Purpose: STATE-02 (persist), STATE-04 (validated/versioned stores), STATE-05 (recoverable error). Article reading NEVER depends on Dexie (D2-13 — fixtures stay bundled JSON).
Output: settingsStore + error classifier; SettingsContext upgraded with persistence + storageState; WipeConfirm + StorageBanner wired into App; green storageFallback unit test + persistence e2e.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dexie IndexedDB ↔ runtime | Persisted ReaderSettings records cross this boundary on read (loadSettings) and write (saveSettings) |
| storage-failure → reader | A caught storage error becomes user-facing copy (banner) — must never leak jargon or crash |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Tampering (V5) | persisted ReaderSettings on read | mitigate | ReaderSettingsSchema.safeParse on every read; corrupt → reason "corrupt" → in-memory DEFAULT_SETTINGS (never the raw record). storageFallback.test asserts the corrupt branch. |
| T-02-05 | Denial of Service (V7) | QuotaExceeded / unavailable storage | mitigate | STATE-05: classify → "unavailable" → StorageBanner + in-memory defaults; reading never blocked (fixtures are bundled JSON, not Dexie). |
| T-02-06 | Tampering (V7) | corrupt/unupgradeable DB | mitigate | Pitfall 8: db.delete() ONLY in WipeConfirm destructive handler (explicit consent); never in a catch block. "Keep reading" preserves in-memory reading. |
| T-02-07 | Information disclosure (V7) | storage-failure banner copy | mitigate | UI-SPEC §Copywriting: user-facing word is "local storage"/"reading history and saved settings" — never "database", "IndexedDB", "corrupt", "Dexie", "Zod", "schema". |
| T-02-SC | Tampering | npm installs | accept | Zero package installs this plan. |
