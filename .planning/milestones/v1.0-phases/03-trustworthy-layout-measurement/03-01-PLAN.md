## Phase Goal

**As a** reader, **I want to** keep reading without interruption while layout measurement settles after a viewport, typography, font, or asset change, **so that** a stale or in-flight result never disrupts the view I am using.

## Plan Purpose

Establish the staleness-safe measurement pipeline end-to-end and wire it into the scrolling reader so PAGE-06 (last-valid-view retention) and PAGE-07 (stale-work can never win) hold in the real browser. This plan uses DOM measurement as the strategy for every block kind; Plan 03-02 refines the engine to add the calibrated Pretext fast path for eligible kinds. The diagnostic substrate (D3-05) is defined here in its full versioned shape so Phase 4's PAGE-09 UI can consume it without retrofitting; in this plan only the staleness/error kinds are emitted.

Output: a working `src/measurement/` domain module + reader integration + unit and e2e proof of the two staleness invariants.
