<objective>
Close the Phase 5 UAT Test 11 MAJOR gap (blockquote highlight renders no inline
mark) by adding recursive per-child highlight-slice computation for blockquote
blocks in BOTH render paths.

Purpose: A kind-based gate in both render paths limits inline <mark> overlay
computation to paragraph + heading. Blockquote is a CONTAINER whose readable
text lives in block.children (nested paragraphs); neither path computes
per-child slices, and the blockquote BlockView recursion does not forward
slices to children. Capture, persistence, and resolution all WORK for blockquote
(D5-07 marks it eligible; blockNormalizedText includes the children's text) —
which is exactly the symptom: the highlight "registers on load but doesn't
appear." This closes the ANNO-01 (create+see) and ANNO-05 (remains attached)
contract for blockquote passages.

Output: Per-child slice threading for blockquote in BlockRenderer.ArticleBody
(scrolling) and fragmentRenderer.PageFragmentView (paginated), reusing the
existing sliceRunsForHighlights + highlightsForBlock helpers unchanged, plus a
jsdom-safe component test covering both paths (whole + sliced entries).
</objective>
