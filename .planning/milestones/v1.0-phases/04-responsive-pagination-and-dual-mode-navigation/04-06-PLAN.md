## Phase Goal

**As a** reader, **I want to** move predictably through complete responsive pages and switch or fall back to scrolling without losing my logical passage, **so that** I can read long-form content in a calm booklike way while retaining stable orientation.

This plan unblocks Plan 04-05's Task 3 human gate. Plan 04-05 surfaced a Rule-4 architectural blocker (see `04-05-SUMMARY.md` §Blocking Finding L74-96): the pagination engine could not paginate ANY corpus fixture because (a) PaginatedSurface replaces the full `ArticleBody` with a single page fragment BEFORE the engine reads live line boxes, and (b) every fixture's container blocks break the engine's 1:1 `article.blocks` ↔ `querySelectorAll(BLOCK_SELECTOR)` assumption. The user approved four locked fixes (Options A + data-block-index + fold-in persistence failures + execution vehicle = Plan 04-06). After this plan, PAGE-03 is provable across the corpus matrix and the phase gate can proceed.

<objective>
Resolve the architectural blocker surfaced by Plan 04-05's corpus-matrix e2e suite by (1) capturing `LineBox[][]` during the measurement phase and threading it through `MeasurementResult` so the engine never re-reads live DOM (Option A), (2) adding a `data-block-index` attribute to each top-level rendered block so the engine + measurement have a guaranteed 1:1 block↔element mapping that container blocks cannot break, (3) removing the engine's `block-element-mismatch` guard and its live `articleEl.querySelectorAll` line-box walk in favor of the pre-captured data, (4) removing the `status !== "ok"` e2e skips so the PAGE-03 corpus matrix actually runs, and (5) fixing the pre-existing `persistence.spec.ts` STATE-01 failures that the paginated default (04-02) + paginated-surface geometry (04-03) introduced.

Purpose: PAGE-03 ("every supported content unit appears exactly once and in canonical order, without clipping, duplication, omission, or nonterminating pagination") is the highest-risk requirement in the prototype and the only remaining blocker for the Phase 4 gate. It is only provable in real browsers; until the engine can paginate the container-bearing corpus, the matrix cannot run.

Output: Schema-evolved measurement carrying per-block line boxes, a container-aware engine that consumes pre-captured data, six unskipped corpus-matrix e2e specs that pass across chromium/firefox/webkit, and a green persistence suite. This plan is `autonomous: true` — the manual screen-reader + reduced-motion checks remain in 04-05 Task 3 (this plan only unblocks the automated gate that precedes it).
</objective>
