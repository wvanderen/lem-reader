## Phase Goal

**As a** reader, **I want to** move predictably through complete responsive pages and switch or fall back to scrolling without losing my logical passage, **so that** I can read long-form content in a calm booklike way while retaining stable orientation.

This plan delivers the **first vertical slice a reader can experience**: open an article in paginated mode, see a real page fragment of the same semantic blocks, and click chevrons to turn pages end-to-end. It consumes Plan 01's engine + Plan 02's readingMode field. Mode-toggle, keyboard bundle, swipe, anchors, and fallback land in Plans 04–05 — this plan proves the pagination pipeline renders and turns.

<objective>
Wire ArticleView to read Phase 3's `useMeasurement()` return (now `{trustedView, diagnostics}` — the SAME DiagnosticBus flows to PaginatedSurface and later Plan 05's banner), derive page fragments via `paginateDocument()`, and render ONE fragment at a time through a new `PageFragmentView` that reuses `BlockView` (no forked renderer — DOC-02 reading order + D-05 integrity + react/no-danger security depend on reuse). The renderer MUST slice paragraph runs via `splitParagraphRuns` when a fragment carries a sub-block grapheme range (startGrapheme>0 or endGrapheme<blockLength) — D4-01 booklike line-boundary splitting requires paragraphs to split, and rendering whole blocks would violate PAGE-03 exactly-once/no-clipping for articles with paragraphs spanning page boundaries. Add quiet page-side chevron buttons (D4-06) for pointer page-turn, the "N of M" indicator (D4-08), and extend ProgressHairline so its fill derives from N/M in paginated mode. Ship the page content-box geometry in authored CSS (no Tailwind).

Purpose: Prove the pagination pipeline works end-to-end (measurement → fragmentation → semantic rendering → chevron turn) before layering full keyboard/swipe/mode-toggle/fallback in later plans. This is the thinnest slice that lets a reader actually turn pages.

Output: One new fragment renderer + one new paginated surface container + one new indicator + one extended hairline + the ArticleView mode-aware branch + page geometry CSS + a component test.
</objective>
