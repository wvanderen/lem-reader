# Phase 8 — UI Design Contract

> Visual and interaction contract for the **Personal Library** surface and the
> **Markdown + HTML-upload** intake extension. Generated by `gsd-ui-researcher`,
> verified by `gsd-ui-checker`. The library replaces `FixtureList` at the `#/`
> default route; the intake extension widens `IngestControl`. Every contract
> below either reuses an existing v1.0/Phase-7 token/pattern verbatim or
> extends the authored-CSS surface in `src/app.css` additively.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — locked stack policy (`STACK.md` "What NOT to Use": no Tailwind, no component suite, no shadcn) |
| Preset | not applicable |
| Component library | none — authored React + native HTML elements (`<dialog>`, `<details>`, `<input type="file">`) |
| Icon library | none — inline SVG glyphs only (mirrors `ProgressHairline`, `SettingsPanel`, `ModeToggle`, `PageTurnControls`) |
| Font | unchanged from v1.0 — `--font-body` serif stack for content; `--font-ui` system-ui stack for chrome |
| Source-of-truth | `src/app.css` (all custom properties already declared in `:root` + `[data-theme="light"|"dark"]` blocks); Phase 8 ADDS selectors under the existing tokens, never re-declares them |

**shadcn gate:** N/A — React/Vite project, but the locked stack (`AGENTS.md` → `STACK.md`) explicitly excludes Tailwind/component suites/shadcn. Authored CSS + custom properties is the project's load-bearing styling contract. Registry safety section is empty by design.

## Component Inventory

All components are **additive**. Existing components are reused unchanged unless flagged.

### NEW: `LibraryView` (replaces `FixtureList` at `#/`)

- **Route:** `#/` (default), unchanged hash router in `App.tsx`.
- **Page heading:** `<h1>Saved articles</h1>` — byte-stable from v1.0 (SC#1 regression target).
- **Structure (DOM order):**
  1. `<h1>Saved articles</h1>`
  2. `<IngestControl />` (existing — extended per D8-15 below)
  3. `<div class="status" role="status" aria-live="polite">` — loading/ready/error for the list itself (mirrors FixtureList's existing region verbatim; byte-stable copy)
  4. `<ContinueReadingStrip />` (NEW — see below; only when ≥1 unfinished article exists)
  5. `<LibrarySearch />` + `<TagFilter />` (NEW — search input + chip strip)
  6. `<ul class="library-list">` of `<LibraryRow />` items

- **Card grid:** reuses `.fixture-list` responsive grid verbatim — 1 column `<640px`, 2 columns `640–1024px`, 3 columns `≥1024px`. Class renamed `library-list` for semantic accuracy; CSS rule identical to `.fixture-list`.

### NEW: `LibraryRow` (one article)

- **Container:** `<li>` with class `library-row` extending `.fixture-list li` geometry (`--surface-raised` + 1px `--hairline` + 4px radius + `--space-lg` padding + 44px min hit area on the title link).
- **Contents (DOM order):**
  1. `<h2 id="title-{id}">` — article title (22px / 600 / 1.3, `var(--font-body)`)
  2. `<p class="meta">` — author when present (omitted otherwise)
  3. `<SourceBadge />` — inline source indicator (D8-02)
  4. `<ProgressHairline />` — per-row progress (D8-11), reused unchanged from `src/reader/ProgressHairline.tsx`; rendered only when `ratio > 0` AND `ratio < 0.98` (zero ratio hides the hairline; ≥0.98 swaps to the "finished" mark — D8-12)
  5. `<FinishedMark />` — small "Finished" label when `ratio ≥ 0.98` (D8-12)
  6. `<ul class="library-row-tags">` of tag chips (only when `article.tags?.length > 0` — display-only, no edit affordance per D8-05)
  7. `<button class="library-row-remove">` — quiet trash affordance opening `LibraryRemoveConfirm`
- **Title link:** `<a href="#/article/{id}" aria-labelledby="title-{id}">Open article</a>` — text byte-stable from v1.0 FixtureList (regression target).
- **Finished threshold:** `0.98` (RESEARCH.md §Pattern 4 recommendation; planner confirms). Mode-agnostic — works for paginated + scrolling.

### NEW: `SourceBadge` (D8-02)

Small text label inside the row, between title/author and the hairline. Renders ONE of five variants based on `article.ingestionMeta?.source ?? "fixture"`:

| Source value | Badge text | Notes |
|--------------|------------|-------|
| `"fixture"` | `Sample` | v1.0 fixtures — reuses existing FixtureList semantics (no source field) |
| `"url"` | `Web` | URL-ingested article |
| `"paste"` | `Pasted` | Phase-7 paste-HTML path |
| `"markdown"` | `Markdown` | Phase-8 `.md` upload |
| `"html-upload"` | `HTML file` | Phase-8 `.html` upload (D8-15) |

- **Styling:** `.meta` (14px / 400 / 1.45 / `var(--font-ui)` / `var(--ink-soft)`), no border, no fill, no icon. Reads as quiet provenance metadata, not as a status pill.
- **Accessibility:** plain `<p class="meta source-badge">` — no role, no aria-label (the text itself is the accessible name).
- **`sourceUrl` link (LIB-05):** when `article.provenance.sourceUrl` is present (url + paste variants), the badge text becomes a link (`<a href={sourceUrl} rel="noreferrer noopener" target="_blank">`) to the original source. Markdown + html-upload + fixture variants render plain text (no source URL to link — D8-17 markdown has no canonical URL). Mirrors the existing ArticleView "Originally published at {domain}" pattern (already shipped in v1.0).

### NEW: `ContinueReadingStrip` (D8-09)

- **Mount condition:** only when ≥1 unfinished article (recently-opened with `progress < 0.98`).
- **Cap:** **3 articles** (calm lower end per CONTEXT.md "Continue-reading strip size cap").
- **Heading:** `<h2>Continue reading</h2>` (22px / 600, mirrors existing section-head baseline).
- **List:** `<ul class="continue-reading">` of up to 3 `<li>` cards, each:
  - Title link (`<a href="#/article/{id}">`)
  - Author `.meta` line (when present)
  - Per-row `<ProgressHairline />`
  - **NO source badge, NO remove affordance, NO tag chips** — the strip is spare and focused on the resume gesture only.
- **Sort:** most-recently-OPENED first (D8-10 — opening counts; `locationStore.savedAt` is the key).
- **CSS class `.continue-reading`** extends the `.fixture-list` grid with `grid-template-columns: 1fr` (always single column — the strip never widens; multi-column would compete with the main list).
- **Hairline between strip and list:** `1px solid var(--hairline)` rule + `--space-lg` margin-block below (calm separation; matches `.app-header` bottom-border discipline).

### NEW: `LibrarySearch` (D8-06)

- **Container:** `<form role="search">` (semantic search landmark).
- **Input:** `<input type="search" id="library-search" name="q">` with `<label class="visually-hidden">Search your library</label>` (the input has an explicit `placeholder="Search by title, author, or tag"` visible to sighted readers; the label is for SR-only context).
- **Filter behavior (D8-06):** client-side linear scan over `compositeLibraryRepository.list()` filtered by normalized title + author + sourceUrl-domain + tag-names. No submit button — filter-on-keystroke (`onChange`).
- **CSS class `.library-search`** — single text input, `--space-md` width 100%, 1px `--hairline` border, 4px radius, `--space-sm` padding, 44px min-height (touch target). `:focus-visible` inherits the global 2px ring.
- **Empty query:** shows all articles (no filter). Active tag filter is preserved independently (D8-07).

### NEW: `TagFilter` (D8-07)

- **Container:** `<fieldset class="tag-filter"><legend class="visually-hidden">Filter by tag</legend>` (the chip strip is a single-select radio-equivalent — `<legend>` provides SR context; chips are `<button aria-pressed>` toggles).
- **Chip:** `<button type="button" class="tag-chip" aria-pressed={active}>` carrying the tag name.
- **Single-select:** activating a chip sets it as the active filter; activating the active chip clears the filter (toggle behavior). Only one tag active at a time (D8-07).
- **Auto-prune (D8-08):** chips render only for tags currently applied to ≥1 article (derived client-side via `Array.from(new Set(articles.flatMap(a => a.tags ?? [])))`). When a tag's last article loses it (or is removed), the chip disappears on next render — no orphan-tag UI.
- **Empty state:** if no article has tags, the fieldset renders nothing (no "no tags yet" copy — spare chrome).

### NEW: `TagChip` (display-only on row; interactive in TagFilter)

- **Display variant (on `LibraryRow`):** `<li><span class="tag-chip tag-chip-readonly">{name}</span></li>` — no `aria-pressed`, no `<button>`. Pure provenance metadata.
- **Interactive variant (in `TagFilter`):** `<button class="tag-chip" aria-pressed={bool}>{name}</button>` — 44px min-height touch target, `--ink-soft` text at rest, `--accent` text + `--accent` border when `aria-pressed="true"`.
- **Common CSS:** `--surface-raised` background, 1px `--hairline` border at rest, 4px radius, `--space-xs` block padding + `--space-sm` inline padding, 14px / 400 / 1.45 `var(--font-ui)`. Never `--accent` background fill (would compete with the row's title link + add a sixth color use).

### NEW: `LibraryRemoveConfirm` (D8-13 / D8-14)

- **Component:** native `<dialog>/showModal` + `role="alertdialog"`, sibling of `WipeConfirm` (`src/reader/WipeConfirm.tsx`).
- **Trigger:** `<button class="library-row-remove">` (trash glyph + visually-hidden "Remove {title}" label).
- **Focus management:** mirror `WipeConfirm` discipline exactly — `triggerRef` capture on open, `data-initial-focus` on the **cancel** button (safer non-destructive default), explicit `.focus()` call after `showModal()` (WebKit quirk per Pitfall 1), focus-restore on `close`.
- **Body copy:** `"Remove this article? Your highlights and notes for it will also be removed."` (D7-04 calm DOC-06 voice — names the consequence without jargon; researcher-recommended copy per RESEARCH.md §Pattern 3).
- **Buttons:** `<button class="library-remove-destructive">Remove article</button>` + `<button class="library-remove-cancel" data-initial-focus>Keep article</button>` — geometry byte-identical to `.wipe-confirm-destructive` / `.wipe-confirm-cancel` (44px min-height, `--destructive` border on destructive, `--hairline` border on cancel, `:hover` inverts destructive to `--destructive` background + `--surface` text).
- **Backdrop:** `rgba(31, 27, 22, 0.5)` — same as `.wipe-confirm::backdrop`.
- **On confirm:** call existing `dexieLibrarySource.remove(id)` (cascade already shipped, Phase 7 Plan 07-06); navigate to `#/`; refresh library list.
- **CSS class `.library-remove-confirm`** — mirrors `dialog.wipe-confirm` geometry verbatim (centered alertdialog, `--surface-raised` background, 1px `--hairline` border, 8px radius, `--space-lg` padding, max-width 480px). One new selector; not a fork.

### NEW: `TagEntry` (D8-05 — in ArticleView)

- **Mount point:** reader chrome inside `ArticleView` (planner confirms exact location — recommended: a quiet strip near the article header, above `.article-body`).
- **Structure:** `<fieldset class="tag-entry"><legend>Tags</legend>` containing:
  - Existing tag chips (display-only, with × remove button per chip — 44px touch target)
  - `<input type="text" id="tag-entry-new">` with `<label>Add a tag</label>` + `<button class="tag-entry-add">Add tag</button>` (44px touch target)
- **Behavior:** typing a tag + Enter or "Add tag" writes to `tagsStore.setArticleTags(articleId, [...current, newTag])`. Pressing × on an existing chip removes that tag.
- **Inert at mount:** does NOT auto-focus on `ArticleView` open (Pitfall 8-5 — focus shift would break v1.0 e2e tests). Reader activates via Tab/Click.
- **Voice:** calm, no jargon ("Tags" / "Add a tag"), matches D7-04.

### EXTENDED: `IngestControl` (D8-15 — adds `.md` + `.html` upload)

The existing `IngestControl` has no authored CSS (`.ingest-control` is unstyled in `app.css`). Phase 8 declares styles for the whole section AND adds the third upload form.

- **Existing forms (unchanged):** `<h2>Add an article</h2>` → URL `<form>` (label "Add by URL", input + "Add" button) → paste-HTML `<form>` (label "Paste HTML", textarea + "Add pasted article" button).
- **NEW form (third sibling):** `.md` + `.html` file upload:
  - `<form>` with `<label htmlFor="ingest-file">Upload a file</label>`
  - `<input id="ingest-file" type="file" accept=".md,.html">`
  - Submit button label: **"Add file"** (verb + noun, mirrors "Add" + "Add pasted article" voice)
- **Layout:** three sibling forms stacked vertically inside the `.ingest-control` section (RESEARCH.md §Open Questions Q2 recommendation — lowest-cost layout; combined/tabbed affordance deferred to a later phase).
- **Client-side size cap:** **5 MB** per file (researcher/planner discretion per CONTEXT.md; reuses the existing `response-too-large` reason via `mapReasonToCopy("response-too-large")` → `"This page is too large."`).
- **Submitting message:** `"Reading file…"` (mirrors existing `"Fetching article…"` for URL/paste — verb + object, calm DOC-06 voice).
- **Success behavior:** navigate to `#/article/{id}` (existing path; success is navigation, no success copy).
- **Dedupe-refuse (D7-07 / D8-18):** `await dexieLibrarySource.has(result.article.id)` before save; on collision, surface `"Already in your library."` via the existing `.status` region. (Existing Phase-7 mechanism — extended to the upload path unchanged.)
- **`.ingest-control` CSS (NEW — covers all three forms):**
  - `<section>` with `margin-block: var(--space-xl)`, `padding: var(--space-lg)`, `background: var(--surface-raised)`, `border: 1px solid var(--hairline)`, `border-radius: 4px` (extends the `.status` card pattern; calm container).
  - `<h2>` 22px / 600 / 1.3 (mirrors existing section heads).
  - Forms stack vertically with `gap: var(--space-md)`.
  - Each `<label>` is 14px / 600 / 1.45 `var(--font-ui)` (Meta-bold — mirrors `.settings-section legend`).
  - Each `<input>` / `<textarea>` / `<input type="file">` is `--space-sm` padding, 1px `--hairline` border, 4px radius, `--surface` background, 44px min-height for text inputs (touch target — A11Y-07). `:focus-visible` inherits the global 2px ring.
  - Submit buttons reuse `.resume-banner-secondary` geometry byte-for-byte (neutral `--hairline` border, `:hover` → `--accent` border + `--accent` text). The URL "Add" / "Add pasted article" / "Add file" buttons all share one class `.ingest-submit`.
  - `.status` region inside the section reuses the existing `.status` class verbatim.

1. No internal jargon — never `fixture`, `Zod`, `schema`, `Dexie`, `transaction`, `cascade`, `slug`, `hash`, `grapheme`, `revision`, `id` in user-facing copy.
2. Sentence case for headings/buttons (mirrors v1.0: "Saved articles", "Add an article", not Title Case).
3. Verbs first on actions ("Add", "Remove", "Keep", "Search").
4. Names the consequence on destructive actions ("Your highlights and notes for it will also be removed" — not just "Are you sure?").
5. Names the recovery path on errors ("Select it again from the list, or try a different article" — not just "Error").
6. Period at end of full sentences in body copy; no period on button labels or single-word badges.

## Interaction Contract

Phase 8 inherits the v1.0 interaction rules (READ-04 calm chrome, A11Y-06 reduced-motion, A11Y-07 44px touch, A11Y-08 live regions, forced-colors safety) **without modification**. The new surfaces extend the same discipline.

1. **Keyboard — library list.** Tab reaches each row in document order; the row title link is the row's primary focus target (44px min). Remove button is a separate tab stop after the title link. Tag chips on the row are NOT tab stops (display-only `<span>`, not `<button>`).
2. **Keyboard — search.** Single tab stop on the search input. Filter-on-keystroke (`onChange`); no submit button. Escape clears the query (mirrors native `<input type="search">` UA behavior).
3. **Keyboard — tag filter chips.** Each chip is a tab stop (`<button>`). Enter/Space toggles `aria-pressed`. Activating the active chip again clears the filter.
4. **Keyboard — continue-reading strip.** Each strip card's title link is a tab stop (44px min). The strip sits above the main list in DOM order so the first resume target is the first focusable article on the page.
5. **Keyboard — remove confirm.** Dialog traps focus (native `showModal`). Default focus lands on **Keep article** (cancel) via `data-initial-focus` (Pitfall 8 — safer non-destructive default). Tab cycles within the dialog. Esc cancels (native dialog behavior). On close, focus restores to the row's remove button (`triggerRef.current?.focus()` — Pitfall 1 discipline).
6. **Keyboard — tag entry.** TagEntry is a normal form fieldset inside `ArticleView`. Tab order: existing chips (× buttons) → input → Add button. **Inert at ArticleView mount** — does not steal focus from the article body (Pitfall 8-5 — focus shift breaks v1.0 e2e tests).
7. **Keyboard — file upload.** Tab order: file-input → submit button. Native file picker opens via Enter/Space on the input. Form submits with the picked file.
8. **Screen-reader live regions.** Two distinct `.status` regions, unchanged from Phase 7: (a) `IngestControl`'s `.status` (idle/submitting/error — `"Fetching article…"` / `"Reading file…"` / refusal phrases) and (b) `LibraryView`'s `.status` (loading/ready/error for the list itself — `"Opening article…"` / `"Couldn't open this article."`). Both `aria-live="polite" aria-atomic="true"`. No new live regions added (the remove-confirm dialog uses `role="alertdialog"` + `aria-labelledby` + `aria-describedby`, not a live region).
9. **Reduced motion (A11Y-06).** No new transition or animation property on any Phase 8 selector. Tag-chip activation, search filtering, hairline fill, and dialog open/close are instant state changes (mount/unmount). The global `prefers-reduced-motion` gate at `app.css` lines 84-92 is trivially satisfied.
10. **Forced colors (A11Y-05).** Tag-chip active state uses `aria-pressed` (conveys state beyond color); "Finished" mark uses text + a filled-circle glyph (shape + text, not color alone); source badge uses text labels (no color-only cue); remove-confirm destructive button uses `--destructive` border + the unambiguous "Remove article" label. All survive `forced-colors: active`.
11. **Focus visibility.** The global `:focus-visible { outline: 2px solid var(--focus-ring); outline-offset: 2px }` rule applies to every new interactive element. No `outline: 0/none` overrides.
12. **Touch targets.** Every interactive control on the new surfaces satisfies `min-height: var(--touch)` (44px) — remove button, tag chip × button, tag-entry add button, search input, file-input submit, ingest submit buttons, continue-reading title links, library row title links. Mirrors A11Y-07.
13. **Calm-chrome rule (READ-04).** No new sticky chrome. ContinueReadingStrip scrolls with content. Tag-filter chips scroll with content. IngestControl scrolls with content. The 48px header (`app-header`) and the 2px `ProgressHairline` (mounted on `ArticleView` only — NOT on `LibraryView`) remain the only sticky chrome.
14. **No new top-layer surfaces.** Only `LibraryRemoveConfirm` is top-layer (`<dialog>/showModal`). TagEntry, TagFilter, LibrarySearch, ContinueReadingStrip, SourceBadge, and LibraryRow are all in-flow inline content.
15. **Hash router unchanged.** Library is `#/`; article is `#/article/<id>`. No router library. The reader's back button returns from `#/article/<id>` to `#/` (the library) — expected behavior; no custom back-affordance on ArticleView.
16. **"Finished" threshold.** `progress ≥ 0.98` ⇒ article leaves ContinueReadingStrip, gains `<FinishedMark>` in the row, hairline renders at `scaleX(1)` (full). Cross-mode (paginated + scrolling) — RESEARCH.md §Pattern 4 recommendation.
