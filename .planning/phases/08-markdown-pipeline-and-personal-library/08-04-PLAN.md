<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| File picker → IngestControl.handleFileSubmit | Untrusted file content crosses here; client-side size cap (5MB) + dispatch by extension |
| Tag input → tagsStore.setArticleTags → Dexie | Untrusted tag-name string crosses here; React escapes text children when rendering |
| RemoveConfirm destructive onClick → dexieLibrarySource.remove | Destructive cascade crosses here; confirmation dialog gates it (Pitfall 8) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-8-14 | DoS | Markdown/HTML content bomb via file upload | mitigate | Client-side 5MB cap in handleFileSubmit refuses oversized files via `mapReasonToCopy("response-too-large")` → "This page is too large." Server re-applies Phase 7's content-length cap. |
| T-8-15 | Tampering | File extension spoofing (.html renamed to .md) | accept | The dispatch-by-extension only chooses the adapter; both adapters run ArticleSchema.parse + assertRoundTripAnchor identically. A .html file mis-dispatched to markdownToBlocks produces plain-text HTML blocks (escaped) which the round-trip gate catches. No security impact — the doc model is the boundary either way. |
| T-8-16 | Tampering / XSS | Tag name injection via TagEntry input | mitigate | Tag names render as React text children (escaped by default); no HTML parsing. Defensive trim/dedupe/empty-drop in TagEntry before calling setArticleTags. |
| T-8-17 | Repudiation / Tampering | Accidental cascade-remove (no confirmation) | mitigate | RemoveConfirm gates the destructive `dexieLibrarySource.remove(id)` behind a native `<dialog>/alertdialog` with `data-initial-focus` on the cancel button (Pitfall 8 — non-destructive default). Body copy names the cascade consequence. |
| T-8-18 | Tampering | Pitfall 8-5 — TagEntry steals focus on ArticleView mount | mitigate | TagEntry is inert at mount: no `autoFocus`, no `useEffect`-driven `.focus()`. Reader activates via Tab/Click. v1.0 e2e tests that assert focus on the article body remain green. |
</threat_model>
