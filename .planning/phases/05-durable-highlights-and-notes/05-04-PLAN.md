## Phase Goal

**As a** reader, **I want to** create, revisit, and manage local highlights and notes, **so that** they remain attached to their intended normalized text across every view change.

> This plan (05-04) closes the two remaining implementation gaps: ANNO-07 ambiguous/orphan surfacing (D5-02/D5-04 — the explicit-state contract that distinguishes this phase from a naive highlighter) and D5-16 cross-fragment rendering (no silent gaps at a page turn). Plan 05-01 shipped the resolveQuoteSelector tri-state; Plans 05-02/03 built the confident-path UI with unresolved CSS + drawer slots pre-stubbed; this plan wires the status DATA through to rendering + drawer + the open-announce, and lands the fragmentRenderer cross-fragment slicing.

<objective>
Wire the `ResolvedHighlight.status` field through to: (1) the inline renderer — an unresolved highlight renders `mark.highlight.unresolved` (dashed outline) at the stored position hint (orphan) or first candidate (ambiguous) instead of a filled mark; (2) the drawer — ambiguous/orphan entries get the flag copy + disabled jump button + enabled delete (the data side of the slots built in Plan 05-03); (3) ArticleView — a one-time `.status` announce on open when ≥1 unresolved highlight exists. Separately, implement D5-16 cross-fragment slicing in `fragmentRenderer.tsx`: intersect each highlight's article-global range with each `PageFragment`'s visible range and render a `<mark>` slice per intersection (all sharing `data-highlight-id`), so a split-block highlight shows on both pages with no silent gap.

Purpose: ANNO-07 is the requirement that makes the anchor model trustworthy (the reader is NEVER silently re-attached to a wrong spot) and D5-16 is the requirement that makes paginated-mode highlights continuous (the reader's mental model that a passage is one thing pagination merely sliced). Both are load-bearing for the "durable" in the phase name.
Output: 1 modified pagination renderer, 1 modified drawer, 1 modified route, 1 CSS finalization, 1 unit test.
</objective>
