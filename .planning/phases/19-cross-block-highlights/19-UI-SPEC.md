# Phase 19 — UI Design Contract

> Visual and interaction contract for **cross-block highlights** (ANNO-08…12).
> Generated by `gsd-ui-researcher`, verified by `gsd-ui-checker`. Phase 19 is a
> near-zero-chrome phase: ONE new refusal hint string, one retired hint string,
> first-fragment excerpts with a calm ellipsis, the existing `<mark>`
> anatomy extended to list items / figure captions / code interiors, and a
> first-slice-only DOM `id` fix. "One highlight is one highlight" (D19-11) — no
> new badges, no span chrome, no new surfaces, no new tokens. Everything else
> is behavior over byte-stable chrome. Zero new packages; zero schema changes;
> zero routes.

## Typography

Phase 19 reuses the existing typography roles **without modification**. No new sizes, no new weights, no new line-heights.

| Role | Size | Weight | Line Height | Phase 19 usage |
|------|------|--------|-------------|----------------|
| Toolbar hint | 14px | 400 | 1.45 | The NEW boundary-ineligible refusal string renders in the existing `.selection-toolbar-hint` register (Meta/Label chrome, `--font-ui`) |

## Color

Phase 19 reuses the existing color tokens **without introducing new color variables or new consumption categories**.

| Role | Value (Sepia default) | Phase 19 usage |
|------|-----------------------|----------------|
| Dominant (60%) | `--surface: #fbf8f3` | Page background — untouched; an interior non-text gap shows plain surface (the ABSENCE of highlight fill is the gap's visual, D19-02 — not a new color) |
| Secondary (30%) | `--surface-raised: #f2ede3` | Toolbar surface (existing); `pre` background (inherited by code marks) |
| Accent (10%) | `--accent: #6b4423` | NOT consumed — no new accent uses. Links inside marks keep their accent + underline (existing rule, extends over spans) |
| Destructive | `--destructive: #9b2c2c` | Delete-confirm destructive button (existing — unchanged copy and styling) |
| Ink | `--ink: #1f1b16` | Mark text (inherited); toolbar hint text (existing) |
| Ink-soft | `--ink-soft: #5c544a` | `.has-note` dotted underline color; `.unresolved` dashed outline color (both extend to new mark sites verbatim) |
| Hairline | `--hairline: #d9d1c2` | Toolbar border (existing) |
| Highlight | `--highlight: #f5e6c8` | The ONE highlight fill — SAME value at every mark site (prose, list items, quotation children, captions, code, footnote-reference runs, paginated slices). Extending the fill to new KINDS of inline mark is the existing consumption class (inline `<mark>` only), NOT a new category |

**Accent reserved for:** (unchanged list from Phase 18) links, quiet-chrome `:hover`/`:focus-visible` states, open/pressed icon-button states, primary-action borders, the global focus ring, the transient restoration marker bar. Phase 19 adds NOTHING to this list.

**One fill, no span styling (D19-11):** a cross-block span is visually indistinguishable from adjacent single-block highlights except by its extent — no borders, no connectors, no bridging chrome between blocks, no per-block tinting, no badges. The rendered marks ARE the extent.

**Forced colors (A11Y-05):** the three-state shape distinction — filled / `.has-note` dotted underline / `.unresolved` dashed outline — extends to EVERY new mark site (captions, code, list items). Shapes survive forced palettes; state is never color-alone. The interior gap needs no forced-colors treatment (absence of fill is engine-stable).

**Theme-portability:** every Phase 19 mark site consumes `var(--highlight)` / `var(--ink)` / `var(--ink-soft)` only. All three themes re-theme automatically, including code marks over `--surface-raised`.

## Component Inventory

All components are **extended or pure-derived**. No new visual surfaces ship. Existing chrome is reused unchanged unless flagged.

### EXTENDED: `SelectionToolbar.tsx` (the D19-06 hint surface)

- The refusal branch keeps its exact anatomy (`.selection-toolbar-hint` replacing the buttons when `!isValid`). The reason→copy union gains `boundary-ineligible` → the NEW string (§Copywriting). The `"multi-block"` reason and its copy RETIRE.
- The buttons variant is UNCHANGED for multi-block selections (D19-09): `Highlight` and `Highlight + note` render and fire exactly as today — no span feedback, no block count, no disabled state for spans. The toolbar's positioning/flip/clamp geometry, `role="toolbar"` + `aria-label="Highlight actions"`, and the polite announce-on-appear region are byte-stable.

### EXTENDED: `HighlightOverlay.tsx` / `capture.ts` (reason union — not visual)

`CaptureResult` retires `"multi-block"` and gains `boundary-ineligible` (+ defensive `empty-span`, mapped to the existing empty-selection copy — no new string). The overlap reason and its check generalize to global ranges (D19-07) with zero copy change.

### EXTENDED: `InlineRenderer.tsx` (first-slice-only DOM id — Pitfall 2)

- `id={`hl-${slice.highlightId}`}` stamps ONLY the first rendered slice of a highlight within the mounted document (scrolling: the article-wide first slice = span start; paginated: the first slice on the mounted page). EVERY slice keeps `data-highlight-id`, `tabIndex={0}`, `aria-haspopup="dialog"`, and its per-slice `aria-label`.
- Mechanism (slice-start-equals-highlight-start check vs renderer first-occurrence pass) is planner territory (19-RESEARCH OQ3); the CONTRACT is: exactly one `id="hl-<id>"` per highlight per document at all times, and it precedes its siblings in document order. Mandatory spec assertion: `[id="hl-<id>"]` count === 1 for a multi-block span in scrolling mode (axe will NOT catch this — 19-RESEARCH Pitfall 2/A1).

### EXTENDED: `BlockRenderer.tsx` (scrolling renderer — the mark-coverage extension)

- **List per-item threading (D19-13/15):** mirrors the shipped 05-07 blockquote `childHighlightSlices` path over the items-shape (`items[i].content[j]`, nested lists recurse). Item interiors render the standard `<mark>` via their InlineList — no new element, no new class.
- **Caption marks (D19-01 + 19-RESEARCH OQ1 recommendation):** `figcaption`'s InlineList consumes highlight slices once the Pitfall 1 alt-offset alignment lands. Mark anatomy identical to prose.
- **Code marks:** `<pre><code>` interiors render `<mark class="highlight">` around verbatim source segments — the same element, inheriting `--font-code`; validity (`mark` inside `code`) and no-geometry-change are the constraints. *(Recommendation: LAND — a span endpoint in code that renders no mark is invisible extent. If the planner scopes code-interior rendering out as the documented per-kind render-coverage fallback (19-RESEARCH OQ1), the matrix must document it honestly; eligibility and excerpt/export behavior are unaffected either way.)*
- **Figure/unsupported interiors:** render NO marks by construction (D19-02) — zero special-casing, zero new code.

### EXTENDED: `fragmentRenderer.tsx` (paginated twin)

The same per-kind threading in entry-local coordinates for the mounted page. A span crossing page boundaries renders marks on EACH page sharing one `data-highlight-id` (the D5-16 split-block rule extended over more blocks). The per-page first slice carries the DOM id (uniqueness is per mounted document).

### NEW: shared first-fragment excerpt helper (pure derivation — D19-10)

One pure helper (e.g. `src/annotations/excerpt.ts`): `firstFragmentExcerpt(exact, maxChars)` → text up to the first `"\n"` (BLOCK_SEPARATOR), length-capped, with `…` appended per the honesty rule. NO React, NO DOM. Adopted at EVERY surface that renders `quote.exact`:

- `ReviewView.tsx` — the visible `.review-quote` AND the excerpt prefixes inside the Edit-note / Remove / Go-to-highlight `aria-label`s
- `AnnotationsDrawer.tsx` — `.drawer-entry-excerpt` + its jump `aria-label`
- `NotePopover.tsx` — `.highlight-popover-excerpt` (both describedby blocks)
- `DeleteHighlightConfirm.tsx` — the `review-remove-excerpt` context block

Existing per-surface caps stay EXACTLY as shipped (review 120/aria 60, drawer 120/60, popover 200, confirm 200) — the helper parameterizes, it does not unify the caps. The inline `<mark>` per-slice `aria-label` KEEPS its slice-local text (first 80 chars of THAT slice's runs) — each mark announces what it contains; span-level extent lives in the review/drawer surfaces.

### EXTENDED: `markdown.ts` (export — D19-12)

A cross-block highlight exports as ONE `HighlightSection` whose quote renders as `> `-prefixed continuation lines — one line per block fragment, `escapeMarkdownLine` applied PER LINE (a later block beginning `#` or `1974.` must not forge structure — the phase's one security-adjacent copy change). Status marker on the first line only.

### REUSED unchanged (surface-stable)

Toolbar buttons + positioning + announce region · `NotePopover` modal-`<dialog>` discipline (H/N shortcuts, focus, excerpt block) · `ReviewRow` anatomy (quote, note preview, badge, date — NO block-count badge, D19-11) · review badge vocabulary (`Uncertain anchor` / `Article missing`) · `DeleteHighlightConfirm` structure, copy, `data-initial-focus` on Cancel · review empty states · `useAnnotationState` create/save flow (overlap check generalizes in place) · footnotes region (bodies stay ineligible — 19-RESEARCH Pitfall 6).

The hint REPLACES the buttons in the toolbar exactly as every refusal does today — one channel, one string, no title-case, no exclamation.

## Interaction Contract

Phase 19 inherits the global interaction rules (READ-04 calm chrome, A11Y-06 reduced-motion gate, A11Y-07 44px touch, A11Y-05 forced-colors, global `:focus-visible` 2px ring) **without modification**.

1. **The toolbar is unchanged for spans (D19-09).** Select across blocks → the same two buttons in the same place with the same labels. No span feedback during selection, no block count, no new affordance. A reader who knows how to highlight knows how to span.
2. **Reject whole, explain once (D19-05/D19-06).** An ineligible boundary (unsupported block, footnote body, outside-root) refuses the ENTIRE selection: buttons are replaced by the one hint string. No narrowing, no guessed shrinkage, no partial creation. The reader re-selects; the hint is the only and sufficient explanation.
3. **Global no-overlap (D19-07).** A new span (single- OR cross-block) may not overlap ANY existing highlight's article-global range — one `rangesOverlap` check, the existing `This overlaps an existing highlight.` hint. Touching endpoints allowed. No per-block special cases.
4. **One identity, per-slice presence (ANNO-09/11).** Every rendered slice is a real `tabIndex={0}` stop with `aria-haspopup="dialog"`; activating ANY slice (click, tap, Enter, Space — the existing delegated `closest("mark.highlight[data-highlight-id]")` path) opens the one popover for the one highlight. Note edit, jump, and delete operate on the whole — never a fragment.
5. **DOM id discipline (Pitfall 2).** Exactly one `id="hl-<highlightId>"` per highlight per mounted document, on the first slice in document order; `data-highlight-id` on every slice. The review deep-link jump (`#/article/<id>/h/<hl>`) focuses `hl-<id>` and therefore lands at the SPAN START — the D10-03 machinery at `position.start`, confirmed as the jump target.
6. **Interior gaps render unmarked (D19-02).** A span crossing a textless figure or unsupported block simply produces no slices there — the fill continues on both sides with plain surface between. No connector, no ellipsis glyph in-content, no dimming. One identity by construction.
7. **Marks alter no geometry — anywhere.** The existing rule (fill wraps text; no line-height/margin/width change; no layout shift on create/remove) extends to list items, captions, and code — including `pre`'s `overflow-x: auto` scroll geometry (a mark must never widen the scroll box). If measurement demands a guard, ONE additive selector under existing tokens is the ceiling (planner-scoped, documented in-plan).
8. **List markers are chrome, never content (D19-14).** Markers stay CSS `::marker`/`start`-attribute chrome — never DOM text. A highlight starting at an item's first character covers TEXT only; the first marked character IS the item's first text character (mandatory matrix assertion). No new marker-rendering path may exist.
9. **Paginated spans are the same rule over pages (D5-16 extension).** Marks render on each mounted page sharing one `data-highlight-id`; no silent gaps at page turns. A native selection still cannot extend past the mounted page — the cross-page refusal spec STAYS green (ANNO-13 is Future; no machinery this phase).
10. **Selection direction is free.** Backwards drags compose identically (DOM Range normalizes to document order); a matrix cell asserts it — no swap code.
11. **Whole-article spans are honest (D19-04).** No block-count or percentage cap. The review row shows the first fragment + `…`; the reader sees the full extent in the article. Long-span re-anchor degradation stays tri-state honest (ambiguous/orphan — never silent).
12. **Keyboard reading order = document order.** Tab walks a span's slices in reading order (the marks are inline in the semantic tree — DOC-02 preserved). No roving tabindex, no grouping chrome.
13. **Forced colors (A11Y-05).** The fill / dotted / dashed tri-state extends to every new mark site — shape-distinct at all times; state never color-alone. Review badges remain text.
14. **Reduced motion (A11Y-06).** Zero new transition/animation/scroll-behavior properties on any Phase 19 selector. Excerpt derivation and id stamping are pure renders — instant state changes.
15. **44px touch (A11Y-07).** Toolbar buttons keep `min-height: var(--touch)` (unchanged). Marks are content, not controls-with-hit-areas; their activation path is the existing one.
16. **StrictMode idempotency.** The excerpt helper and first-slice id derivation are pure functions of (slices, order) — twin-mount renders are byte-identical.
