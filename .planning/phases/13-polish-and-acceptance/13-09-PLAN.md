<objective>
Close gap G4 from the Phase 13 user review (13-UAT.md § Gaps, 13-VERIFICATION.md § Gaps Found): opening an article in paginated mode first paints the scrolling surface and its progress hairline, then swaps to the paginated surface — a visible jump on every paginated first load.

Root cause: `paginatedActive = isPaginated && trustedView !== null && articleEl !== null` gates both the article element's `paginated-surface` class and the render branch. Until measurement commits, React mounts the scrolling ArticleBody (plus the scrolling ProgressHairline via the `!paginatedActive` gate) — a full scroll-then-swap before pagination settles.

This is the deferred "no-reflow-at-all reading surface" idea being pulled forward BY RECORDED USER DIRECTION (13-UAT.md G4 sanctions "a stable placeholder until pagination settles" — it partially supersedes the D13-03 settings-flash-only boundary). The fix: while the effective mode is paginated but pagination has not settled, render a stable placeholder inside the real paginated frame — never the scrolling surface.

Implementation shape (all inside ArticleView.tsx; PaginatedSurface/engine untouched):
1. New derived flag `paginatedPending = isPaginated && !paginatedActive`.
2. The `<article>` className and `<main>`'s `paginated-main` class gate on `isPaginated` (not paginatedActive) so the pinned-height frame (fixed viewport height + grid + overflow locks via html/body :has) is present from the first paint through the pending window — the frame never changes shape when pagination commits.
3. Pending branch renders the hidden `.article-body-measurement` clone (hoisted so it mounts whenever the effective mode is paginated — it is already the measurement source in the active state per Plan 04-08) plus `.page-viewport` holding a calm `role="status"` placeholder paragraph. Zero new CSS — the frame rides the existing pinned classes and the paragraph rides the existing `.meta` typography.
4. The scrolling ProgressHairline gate changes from `!paginatedActive` to `!isPaginated` — the scrolling hairline never paints while the effective mode is paginated.
5. The geometry effect's reads stay gated so the first publication still carries the page height + `firstPageReservedPx` reserve together: inside the rAF, after the cancelled check, the reserve measurement runs as today, and the `.page-viewport` height read only proceeds when the effective mode is paginated AND trustedView has committed (with the class now present during pending, the old class-presence check alone would read the height before the reserve exists — an early reserve-less first publication, the exact 13-04 Deviation-class regression). Update the explanatory comment to the new gating story (prose avoiding greppable property tokens).

The spec is strengthened to the user bar (13-VERIFICATION.md: "gap plans must strengthen the specs"): a navigation-start recorder proves the scrolling surface never paints in paginated mode and the header never moves.

Fallback interplay preserved: if the engine emits dom-fallback, the session-mode override flips to scrolling, `isPaginated` goes false, classes revert, and the scrolling body mounts with the honest banner — a disclosed mode change, not a jump.

Purpose: zero jumping on paginated first load — POLISH-01/02's mode-surface aspect at the user's bar.
Output: pending-branch render fix + a first-paint mode-surface e2e contract on 3 engines.
</objective>
