## Phase Goal

**As a** reader, **I want to** move predictably through complete responsive pages and switch or fall back to scrolling without losing my logical passage, **so that** I can read long-form content in a calm booklike way while retaining stable orientation.

This plan delivers **full dual-mode navigation**: the mode toggle (header button + M shortcut), the complete page-turn input bundle (keyboard + chevrons + swipe), context-aware focus (D4-07), concise SR announces, and the passage-preservation anchors for both mode-switch (D4-10) and repagination (D4-11). After this plan a reader can switch modes and turn pages every supported way without losing their place.

<objective>
Add `ModeToggle` (header button + `M` shortcut + polite announce) wired through `SettingsContext.update({readingMode})` (D4-09). Add `PageTurnControls` mounting the full keyboard bundle (PageUp/PageDown + ArrowLeft/ArrowRight + Space/Shift+Space per D4-05), wiring the chevrons from Plan 03 to a shared turn handler, adding single-touch horizontal swipe (D4-06, multi-touch stays native pinch-zoom), context-aware focus restoration (D4-07), and the debounced "Page N of M" polite announce. Wire the D4-10 mode-switch anchor (top-of-view → grapheme offset → target, reusing `computeOffset` + `findScrollTarget`) and the D4-11 repagination anchor (same rule on trustedView commit). Extend Header to host the toggle inline-start of the gear without growing the header.

Purpose: PAGE-01 (explicit mode switch) + PAGE-02 (full input bundle) + PAGE-05 (passage preserved through switch + repagination). The fallback banner + diagnostic surfacing + corpus-matrix proofs land in Plan 05.

Output: Two new control components + Header extension + ArticleView anchor wiring + CSS + two component tests.
</objective>
