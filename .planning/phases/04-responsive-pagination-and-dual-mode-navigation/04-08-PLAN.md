CROSS-PHASE regression fix: Phase 3 PAGE-06 (last-valid-view) and PAGE-07 (stale-epoch drop) were regressed by Phase 4 modifications to src/measurement/engine.ts (Plan 04-06's partial-DOM defense).

Plan 04-06 added a defense: "if blocks.length !== article.blocks.length, silently return without committing." The intent was to preserve the prior trustedView when PaginatedSurface replaces ArticleBody (the ResizeObserver would fire against the page fragment, measure partial blocks, and otherwise overwrite the good trustedView).

The defense is misbehaving in two observable ways:
1. PAGE-06: after a re-measure (resize), article DOM loses content (child count drops 9→7). The defense should PRESERVE the prior view; instead the article is losing 2 blocks.
2. PAGE-07: rapid-trigger race commits the wrong (older) constraints' view (committed size 18 when 24 expected). The defense + epoch guard interaction is DROPPING the final valid commit because by the time the final constraints' result arrives, PaginatedSurface has mounted (tripping the defense). The last successful commit was for the older (size 18) constraints.

Purpose: Restore Phase 3's success criteria — PAGE-06 + PAGE-07 must hold for Phase 4 to claim "the prior phase's substrate is preserved."
Output: engine.ts fix + (possibly) useMeasurement.ts seam fix + 3 e2e cells green per spec.

  <action>
    The defense at engine.ts L164-166 reads `if (blocks.length !== this.opts.article.blocks.length) return;`. This skip-without-commit was intended to preserve the prior trustedView, but it has two compounding faults:

    FAULT 1 (PAGE-06 child-count drop): the silent return DOES preserve trustedView, but the resize itself causes PaginatedSurface to re-render. PaginatedSurface's pagination effect (L157-256) has deps `[article, trustedView, articleEl, pageContentBoxHeightPx, diagnostics]`. When pageContentBoxHeightPx changes (resize → articleEl.getBoundingClientRect() updates), the effect re-runs paginateDocument. If trustedView was preserved but pageContentBoxHeightPx shrank, the new pages may be tighter (fewer blocks per page), and the rendered fragment shows fewer block-children — observable as a child-count drop in the article DOM. The defense is not the direct cause; the pageHeight re-derivation cascade is.

    FAULT 2 (PAGE-07 final-commit drop): when PaginatedSurface mounts (initial trustedView commit), ArticleBody unmounts. The ResizeObserver fires on the page-fragment geometry change. The next measureAllBlocks reads `[data-block-index]` against the page fragment (2-3 blocks), the defense returns silently, NO commit happens for the new constraints. The rapid-trigger race's FINAL constraints (size 24) arrives after PaginatedSurface has mounted → defense skips → committed stays at size 18.

    Fix path (the executor MUST confirm by running the failing e2e with logging before patching):
    1. The partial-DOM defense should NOT be the commit gate. Replace it with: when measureAllBlocks returns a partial block list (length < article.blocks.length), emit a `late-epoch-drop` diagnostic (informational — this is expected when PaginatedSurface is mounted) AND return WITHOUT committing. The prior trustedView stays. This matches the current behavior but makes it explicit and instrumented.
    2. To fix PAGE-07: the partial-DOM defense must NOT silently swallow the FINAL valid commit. The simplest correct fix: track the LATEST constraints the engine was asked to measure (this.latestConstraints). When a subsequent run() with NEWER constraints sees a partial-DOM result, it must NOT commit — BUT the trustedView already reflects the LAST commit that succeeded for the FULL article body. The stale-drop.spec.ts assertion checks `window.__lemLastTrustedConstraints` — the DEV hook in useMeasurement.ts L132-136. That hook only updates when setTrustedView fires. If the partial-DOM defense blocks all commits after PaginatedSurface mounts, the hook stays frozen at the initial commit (size 18).
    3. The clean fix: ALWAYS allow measurement against the FULL ArticleBody. PaginatedSurface must NOT replace ArticleBody; instead, ArticleBody must stay mounted (off-screen or visually-hidden) so measureAllBlocks always sees the full article. ALTERNATIVELY: useMeasurement's coalescer must NOT trigger a re-measure on page-only geometry changes (the pageContentBoxHeightPx change is owned by PaginatedSurface's pagination effect, not the engine). ALTERNATIVELY: cache the last full-article measurement and skip re-measurement entirely when ONLY viewport changes (the pre-captured line boxes are viewport-independent; the engine can re-derive pages against the new pageContentBoxHeightPx without re-reading DOM).
    4. The executor must pick ONE of those three approaches by diagnosing which is the root cause.     - PAGE-06: re-measurement (viewport resize) does not reduce article DOM child count.
    - PAGE-07: the FINAL constraints (size 24) is the committed trusted view's `.constraints.size` value after the rapid-trigger race settles.

Replace it with: measureAllBlocks always returns the full article blocks (render ArticleBody off-screen inside PaginatedSurface, OR have ArticleView mount a hidden ArticleBody alongside PaginatedSurface, OR have measureAllBlocks read from a cached clone of the article element captured at initial mount). This is the cleanest fix but touches the most files.

The coalescer currently fires on ResizeObserver against articleEl; when PaginatedSurface mounts, articleEl's geometry is the page box, not the article body. The coalescer should observe the ARTICLE BODY element specifically (the off-screen full render), not the page box.
