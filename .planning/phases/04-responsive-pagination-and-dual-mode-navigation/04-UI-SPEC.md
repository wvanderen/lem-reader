# Phase 4 — UI Design Contract

> Visual and interaction contract for the Responsive Pagination and Dual-Mode
> Navigation phase. Generated by gsd-ui-researcher; to be verified by
> gsd-ui-checker.
>
> **Extends** `01-UI-SPEC.md` and `02-UI-SPEC.md` (read both first). This phase
> reuses Phase 1+2's spacing scale, type scale, color tokens, copywriting
> rules, and interaction baselines verbatim; new surfaces (mode toggle,
> page-turn controls, "N of M" indicator, pagination fallback banner) are
> specified here and MUST stay consistent with the calm/booklike foundation.
> Phase 3 produced no UI-SPEC — its UI surface was invisible-by-default
> (D3-04) and is the substrate Phase 4 now surfaces.

---

## Phase Scope

Phase 4 delivers the **paginated reading mode** and **dual-mode navigation**
that lets the reader move predictably through complete responsive pages and
switch (or fall back) to scrolling without losing their logical passage. It
consumes Phase 3's trusted measurement and produces **explicit source-range
page fragments rendered semantically** (STACK.md: project-owned pagination
engine, NOT CSS columns, NOT Paged.js). It surfaces Phase 3's diagnostic
substrate as reader-visible fallback reasons (PAGE-09).

**In scope (Phase 4):**
1. A quiet **mode-toggle control** in the existing slim header (D4-09) +
   the `M` keyboard shortcut. Switches the same article between paginated
   and scrolling modes while preserving the reader's logical passage
   (D4-10 anchor = top-of-current-view → D-05 grapheme offset → target).
2. A **paginated reading surface** that renders explicit source-range page
   fragments of the same semantic blocks scrolling mode renders (D4-01
   booklike flow — split at line boundaries; D4-02 atomic kinds; D4-03
   heading widow rule; D4-04 line-level widow/orphan = 2).
3. **Page navigation controls** (D4-05 full keyboard bundle + D4-06 quiet
   page-side chevron buttons + left/right swipe), with context-aware focus
   (D4-07) and a concise screen-reader "Page N of M" status (A11Y-08).
4. A **"Page N of M" progress indicator** in the hairline region (D4-08).
   The Phase 2 hairline DERIVES from N/M in paginated mode and stays
   scroll-ratio in scrolling mode (one quiet signal, two modes).
5. **Passage preservation on repagination** (D4-11 — same anchor rule as
   mode switch). Pairs with PAGE-06: the old page stays mounted during
   compute (Phase 3's `trustedView` retention), the new page anchors to the
   same grapheme offset when it commits.
6. A **pagination fallback banner** in the `.status` region (D3-04, PAGE-04,
   PAGE-09) when oversized or unsupported content forces scrolling fallback.
   Dismissible, non-modal, never blocks reading.
7. A new **`readingMode: "paginated" | "scrolling"` preference** in
   `ReaderSettingsSchema` (D4-12, schemaVersion 1→2, default `"paginated"` —
   PROJECT.md: "Pagination is the distinctive default experience, but it is
   not mandatory").

**Out of scope (deferred):**
- **Highlights and notes** — Phase 5 (ANNO-01…07, STATE-03). Phase 4's
  source-offset fragments and D-05 grapheme coordinate are the substrate
  Phase 5 anchors against. D4-06 (no invisible click zones) was chosen
  partly to avoid conflict with Phase 5 text selection.
- **Formal cold/warm repagination performance budgets** (ACPT-04) — Phase 6.
  Phase 4 repagination must FEEL responsive (inherits Phase 3 coalescing +
  staleness pipeline), but formal budget acceptance is Phase 6.
- **Heading navigator and line-focus aid** (ORNT-01/02) — v2. Phase 4
  claims the arrow keys (D4-05); v2 will disambiguate if a line-focus aid
  needs them.
- **Mandatory page-turn animation** — explicitly Out of Scope per
  REQUIREMENTS.md (mandatory motion conflicts with the reduced-motion
  contract). Page turns are instant under reduced motion and instant-by-
  default otherwise (calm aesthetic; no decorative transition).
- **The PAGE-04/PAGE-09 fallback-area discussion was deferred by the user
  in CONTEXT.md.** The constraints are locked (D3-04 surface, D3-05 shape,
  STACK.md behavior); the empirical threshold + per-block-vs-whole-article
  fallback + banner copy + reader-visible-vs-silent-record kind mapping
  are researcher calls settled in this spec (see Copywriting + Interaction
  §19 + §20).

**Locked by STACK.md / AGENTS.md (do not revisit):**
- **Project-owned pagination engine** producing **explicit source-range
  page fragments rendered semantically** — NOT CSS columns, NOT Paged.js,
  NOT Vivliostyle. "Render only complete semantic blocks where possible;
  when text must split, preserve source offsets and accessible reading
  order."
- **Persisting derived page boundaries is FORBIDDEN.** Paginated mode is
  recomputed on every trigger (viewport, typography, font, asset); never
  stored.
- Authored CSS layers + CSS custom properties (NO Tailwind, NO component
  suite, NO shadcn).
- Semantic HTML as the renderer; **DOM reading order equals document
  order** in both modes; **only the current page is in the tab/reading
  order** in paginated mode (A11Y-03 — no duplicate active content tree).
- React 19 + TypeScript + Vite 8 SPA; React state/context only (no
  Redux/Zustand); pagination state is React state/local.
- Playwright across Chromium/Firefox/WebKit for layout truth — pagination
  correctness (PAGE-03 "exactly once, no clipping/duplication/omission/
  nonterminating") MUST be validated in real browsers across the 6-fixture
  corpus × viewport × typography matrix, NOT in a DOM emulator.

**Locked by Phase 1 + 2 UI-SPEC (carried forward unchanged):**
- Spacing scale (multiples of 4) and the 44px `--touch` minimum.
- Type scale: exactly 4 sizes (14 / 18 / 22 / 32px), 2 weights (400 / 600).
- Body serif / UI sans / code mono font stacks.
- Warm-paper color tokens (Sepia default + Light + Dark via `[data-theme]`)
  + accent reserved-for list + contrast contract.
- Copywriting microcopy rules (sentences not fragments; direct second
  person; never blame the reader; never leak jargon — "article" not
  "fixture"; "page" not "fragment").
- Interaction baselines: visible focus (2px outline + 2px offset),
  reduced-motion gate, forced-colors gate, programmatic status pattern,
  always-underlined links, the `.status` card pattern (D2-13), the slim
  persistent header (D2-02), the hairline + SectionAnnouncer (D2-12).
- Layout breakpoints and the invariant calm reading measure.

**Locked by Phase 3 (consumed, not re-implemented):**
- `MeasurementResult` + `BlockMeasurement` (`src/measurement/types.ts`) —
  per-block `{kind, heightPx, lineCount}`. Phase 4 EXTENDS measurement to
  carry split-point data (Pretext line-break positions + grapheme offsets
  for eligible kinds; DOM `getClientRects` line-box mapping → source offset
  for DOM-measured splitting kinds). The extension mechanics are
  architecture; the contract (D-05 grapheme round-trip) is locked.
- `useMeasurement(article, articleRef)` → `trustedView` — the staleness-safe
  source Phase 4 reads. ArticleView currently ignores the return value;
  Phase 4 wires it in.
- `DiagnosticEvent` 6-kind discriminated union (D3-05) — Phase 4 extends
  EMISSION, not the shape. The 6 kinds are the FULL closed set; Phase 4
  does not add a 7th.
- Font-gate (D3-06) + cancel-in-flight + epoch commit guard (D3-07) = the
  staleness contract PAGE-05/SC4 relies on. Phase 4 consumes
  `useMeasurement()`'s trusted view; it does not re-implement trust.
- `.status` live region is RESERVED for consequential fallback events
  (D3-04) — PAGE-09 surfaces there; routine repagination is silent.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (authored CSS layers per STACK.md; shadcn/component suites forbidden) |
| Preset | not applicable |
| Component library | none — semantic native HTML elements only (`<article>`, `<header>`, `<main>`, `<section>`, `<button>`, `<span>`, the existing `<details>`/`<dialog>` patterns). Page fragments render the same native elements (`<h2>`–`<h4>`, `<p>`, `<blockquote>`, `<li>`, `<pre><code>`, `<figure>`+`<figcaption>`, `<sup>`) scrolling mode renders — NO fork of `BlockRenderer`. |
| Icon library | none. The mode-toggle glyph, page-turn chevrons, and any fallback-banner icon are inline SVG (no library). All icons MUST carry an accessible name via `aria-label` or visually-hidden text and MUST be `aria-hidden="true"` when decorative. |
| Font | System stacks only (no web fonts this phase). See Typography. |

**Settings application path (carried from Phase 2 + extended):** preferences
resolve to a `data-theme="..."` attribute on `<html>` (theme) plus CSS
custom properties on `:root` (family/size/measure/spacing) written by
`SettingsContext.applyTheme`. Phase 4 adds **`readingMode`** to the same
write-through (D4-12): the persisted preference flows through `SettingsContext`
and ArticleView branches its render on the resolved value. The mode-toggle
control writes immediately (live, like every other settings control — D2-03)
and persistence is debounced; there is **no Save / Commit step**.

## Spacing Scale

Carried forward verbatim from Phase 1+2. All spacing MUST round to a token
here. Phase 4 adds no new tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap, hairline offset, dense inline padding |
| sm | 8px | Compact control spacing, "N of M" internal padding, banner internal padding, page-side chevron inset from viewport edge |
| md | 16px | Default element spacing, banner copy rhythm, page-side chevron hit-area padding |
| lg | 24px | Section padding, header horizontal padding, fallback-banner padding |
| xl | 32px | Layout gaps, page internal padding (paginated surface top/bottom inset) |
| 2xl | 48px | Major section breaks, page bottom inset (the "calm book margin") |
| 3xl | 64px | Page-level top/bottom padding of scrolling view (unchanged) |
| touch | 44px | Minimum interactive hit area — mode toggle, page-turn chevrons, fallback-banner dismiss ×, every prior-phase control |

**Exceptions (override the scale where stated):**
- **Touch target minimum: 44 × 44 px** (`--touch`) for EVERY interactive
  control added this phase (mode toggle, both page-turn chevrons,
  fallback-banner ×). The page-side chevrons have a 44 × 44 px hit area
  but a smaller visible glyph (24 × 24 px) — see Layout §Page-turn button
  geometry.
- **Focus ring: 2px solid `--focus-ring` outline + 2px offset** (Phase 1
  baseline; applies to all new controls).
- **Header height: 48px** (unchanged — Phase 4 fits the new mode toggle
  inside the existing slim header; the header does NOT grow).
- **Progress hairline: 2px** tall (unchanged — Phase 4 reuses the same
  hairline; only its fill source changes between modes).
- **Reading measure: typographic `ch` units** (unchanged). The page
  content-box width follows `--measure` exactly like scrolling mode — both
  modes share the same calm measure so the eye rests in the same place.
- **Page geometry (new — D4 page-geometry discretion):** the paginated
  page content-box is `width: var(--measure)` and `height: calc(100vh -
  48px - 2px - 2 * var(--space-2xl))` (viewport minus header, hairline,
  and a `2xl` (48px) top + bottom "book margin"). The `2xl` margin is the
  booklike breathing room that distinguishes a page from a scrolling column;
  it is NOT a typographic token, it is a fixed page inset. The reader's
  chosen typography settings (size/measure/spacing) reflow inside this box
  and trigger repagination via the existing `ResizeObserver` surface.

## Typography

Phase 1+2's type scale and font stacks are the **defaults** and remain in
force for every surface. Phase 4 adds no new role. The "Page N of M"
indicator (D4-08) and the mode-toggle's `aria-label` reuse existing roles.

**Font stacks (system-only — no web fonts this phase):**

| Role | Stack | Mutability |
|------|-------|------------|
| Body — serif (D-07 default) | `'Iowan Old Style', 'Source Serif Pro', 'Source Serif 4', Georgia, Charter, 'Times New Roman', serif` | User-selectable |
| Body — sans | `system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif` | User-selectable |
| Body — dyslexia-friendly | `Verdana, Tahoma, 'Segoe UI', Geneva, sans-serif` | User-selectable |
| UI chrome (header, toggle glyph, "N of M", banner copy, status) | `system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif` | Fixed |
| Code / preformatted | `ui-monospace, 'SF Mono', SFMono-Regular, Menlo, Consolas, 'Liberation Mono', monospace` | Fixed |

**Type scale (unchanged from Phase 1+2 — exactly 4 sizes, 2 weights):**

| Role | Size | Weight | Line Height | Stack |
|------|------|--------|-------------|-------|
| Body | 18px *(default; user-steppable)* | 400 (regular) | preset-driven | selected body stack |
| Meta / Label | 14px | 400 (regular) | 1.45 | UI sans |
| Subheading (h2, h3, h4) | 22px *(relative `em`)* | 600 (semibold) | 1.3 | selected body stack |
| Display (article title h1) | 32px *(relative `em`)* | 600 (semibold) | 1.2 | selected body stack |

**Phase 4 surface assignments (no new role, just role assignment):**

| Surface | Role | Notes |
|---------|------|-------|
| Mode-toggle glyph (header) | n/a — SVG only | No visible text label; `aria-label` carries the name. The visible state is conveyed by glyph + `aria-pressed` (forced-colors safety). |
| "Page N of M" indicator (hairline region) | Meta / Label (14px UI sans, `--ink-soft`) | Quiet glanceable signal. NEVER accent-colored. Reads like the meta line under an article title. |
| Page-turn chevron glyphs (page sides) | n/a — SVG only | `aria-label` per control. `--ink-soft` default; `--accent` only on hover/focus (matches the gear-button discipline). |
| Fallback-banner heading | Meta / Label (14px UI sans, 600 weight, `--ink`) | Mirrors StorageBanner / ResumeBanner heading role. The 600 weight (vs the 14px/400 banner body) preserves heading/body hierarchy within the single declared Meta/Label size. |
| Fallback-banner body | Meta / Label (14px UI sans, 400 weight, `--ink-soft`) | Mirrors StorageBanner / ResumeBanner body role. |
| "Page N of M" SR announce (on turn) | n/a — live-region text only | Concise: "Page N of M." Mirrors the SectionAnnouncer pattern. |

**Relative-unit rule (carried from Phase 2):** the px values above are the
defaults at the default body step (18px). Subheading and Display sizes MUST
be expressed as relative `em` units so the hierarchy never inverts when the
reader picks a large body step. The "N of M" indicator and banner copy are
fixed UI-sans px sizes (they do not scale with body — they are chrome, not
prose).

**Block rhythm:** unchanged from Phase 1 inside the page content-box
(paragraph `margin-block: 1em 1em`; `h2` `1.5em 0.5em`; etc.). The `em`-based
rhythm MUST be preserved so a size change inside paginated mode stays calm.
The page itself adds no per-block padding beyond the `2xl` page margin.

**Live-apply (D2-03 extended):** every typography control continues to write
through to `:root` custom properties immediately; in paginated mode this
triggers repagination via the existing `ResizeObserver`/typography-change
trigger surface (Phase 3 already wires typography changes to measurement
invalidation). Persistence is debounced; there is no Save step.

## Color

Phase 4 keeps every Phase 1+2 token. **No new tokens, no new themes.** The
new controls and surfaces are assigned to existing tokens per the
accent-reserved discipline.

### Theme tokens (unchanged — Sepia default + Light + Dark via `[data-theme]`)

Sepia = Phase 1 `:root` defaults. Light + Dark overrides via
`[data-theme="..."]` on `<html>` (Phase 2 D2-09). All token values verbatim
from `02-UI-SPEC.md §Color`; reprinted in `src/app.css`.

### Role usage (60/30/10)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surface` | App background, article-view background, paginated page background, header background |
| Secondary (30%) | `--surface-raised` | Settings panel surface, resume / storage / **pagination-fallback** banner surface, wipe-confirmation surface, code blocks, figures (unchanged) |
| Accent (10%) | `--accent` | See reserved-for list below |
| Destructive | `--destructive` | "Reset local data" destructive action border + the warning icon in the storage-failure banner only. **Phase 4 adds NO destructive actions** — the pagination fallback is reversible (the reader can re-toggle paginated mode); it is NOT destructive and MUST NOT use `--destructive`. |

**Accent reserved for (explicit list — never "all interactive elements"):**
1. Hyperlinks inside the article body.
2. The original-source URL link in the provenance block.
3. The "Open article" CTA on each fixture-list row (Phase 1).
4. The collapsed-state marker on each unsupported-content disclosure (Phase 1).
5. `:focus-visible` outline on every focusable element.
6. The progress-hairline fill (Phase 2 D2-12) — **derived from N/M in
   paginated mode (D4-08), scroll-ratio in scrolling mode**.
7. The gear icon when the panel is open (Phase 2 — active affordance only).
8. The selected-state indicator on the active theme / preset / size /
   measure option (Phase 2).
9. **Phase 4 additions (minimal):**
   - The **mode-toggle glyph when `aria-pressed="true"`** (paginated
     active — mirrors the gear-open rule; closed state uses `--ink-soft`).
   - The **page-turn chevron on hover and on `:focus-visible`** (matches
     the gear-button hover discipline; default state is `--ink-soft` so
     the controls recede).

Accent MUST NOT be used for: body text, headings, chrome backgrounds,
dividers, captions, panel section headings, banner body copy, decorative
elements, the closed-state gear icon, **the "Page N of M" indicator**, **the
default-state page-turn chevrons**, **the default-state mode-toggle glyph**,
or the pagination-fallback banner body copy. Chrome stays on `--ink-soft`;
accent is reserved for the active/hover/focus state and the hairline fill.

### Contrast contract (checker validates, every theme — unchanged from Phase 2)

- `--ink` on `--surface`: ≥ 4.5:1 (body text).
- `--ink` on `--surface-raised`: ≥ 4.5:1.
- `--ink-soft` on `--surface`: ≥ 4.5:1. **The "Page N of M" indicator and
  the default-state page-turn chevrons MUST meet this threshold** (they are
  `--ink-soft` on `--surface`) — if a future token revision weakens this
  contrast, these quiet signals become invisible.
- `--accent` on `--surface` and on `--surface-raised`: ≥ 4.5:1 (links count
  as body text).
- `--focus-ring` against any surface it appears on: ≥ 3:1 (WCAG 2.2 SC
  1.4.11).
- Forced-colors mode (`@media (forced-colors: active)`, already global in
  `app.css`) MUST NOT remove: link underlines, focus outlines, the
  disclosure marker, the selected-option indicator, the gear's open/closed
  distinction, **the mode-toggle's pressed/unpressed distinction** (also
  conveyed by `aria-pressed` + a glyph change), **or the page-turn
  chevrons' enabled/disabled distinction** (also conveyed by `aria-disabled`
  + a glyph opacity change so it is not color-alone).

## Copywriting Contract

Phase 1+2's copywriting and microcopy rules carry forward unchanged
(sentences, not fragments; direct second person; never blame the reader;
never leak internal jargon — no "fixture," "fragment," "source-range,"
"block," "Pretext," "calibration," "drift," "epoch," "grapheme," "schema,"
or "DiagnosticEvent" in user-facing copy; dates via `Intl.DateTimeFormat`).
The new Phase 4 surfaces:

| Element | Copy |
|---------|------|
| Header — mode-toggle button (`aria-label`, paginated state) | `Reading mode: paginated` — followed by the visible state conveyed by `aria-pressed="true"` + a glyph change. Never "paged" or "book mode." |
| Header — mode-toggle button (`aria-label`, scrolling state) | `Reading mode: scrolling` — `aria-pressed="false"`. |
| Header — mode-toggle SR announce on switch (polite) | Switched to paginated reading. / Switched to scrolling reading. (concise — names the new mode; never announces the offset math) |
| Mode-toggle — `M` keyboard shortcut hint (visually-hidden, appended to the `aria-label` when focus is on the toggle) | (Space-visible to AT only) — `Reading mode: paginated. Press M to switch.` / `Reading mode: scrolling. Press M to switch.` |
| Page-turn — Previous page button (`aria-label`) | `Previous page` (always; never "back" or "left") |
| Page-turn — Next page button (`aria-label`) | `Next page` (always; never "forward" or "right") |
| Page-turn — Previous page button (`aria-label`, at page 1) | `Previous page` with `aria-disabled="true"` — the label does NOT change to "no previous page" (the label is a stable control name; disabled state is conveyed by `aria-disabled` + opacity) |
| Page-turn — Next page button (`aria-label`, at last page) | `Next page` with `aria-disabled="true"` — same rule |
| Page-turn — SR announce on turn (polite, A11Y-08) | Page {N} of {M}. (concise — never re-reads content; never announces "you turned the page"; never chatters on rapid turns — debounced per §Interaction 15) |
| Hairline region — "N of M" visible indicator (paginated mode) | `{N} of {M}` — quiet Meta/Label text, `--ink-soft`, no verb. Updates instantly on every turn. |
| Hairline region — visible indicator (scrolling mode) | *(empty — the hairline fill stays scroll-ratio; no "N of M" text in scrolling mode)* |
| Pagination fallback banner — heading | **This part of the article is too large to fit on one page.** |
| Pagination fallback banner — body | Switched to scrolling so you can keep reading. You can switch back to pages anytime. |
| Pagination fallback banner — dismiss | `aria-label="Dismiss"`; visible × glyph |
| Pagination fallback banner — polite announce on appearance | Switched to scrolling reading. |
| Pagination fallback banner — Switch back to pages (secondary, optional) | **Switch to pages** (verb + noun — names the recovery; NOT destructive; the reader returns to paginated mode at the same passage via D4-10 anchor) |
| Article view — keyboard-help affordance | The `M` shortcut and the page-turn keys are documented in a single concise visually-hidden paragraph at the top of the article (mirrors the skip-link pattern): `Keyboard shortcuts: M switches reading mode. PageUp and PageDown, ArrowLeft and ArrowRight, and Space and Shift+Space turn pages.` (announced once to AT on article open; never visible) |
| Article view — "back to list" affordance | Reuses Phase 1+2 flow (hash routing to `#/`); no new chrome copy required. |
| Destructive confirmation | **None — Phase 4 has no destructive actions.** The pagination fallback is reversible (Switch to pages); the mode toggle is reversible; the dismiss × on the fallback banner only hides the banner, not the fallback. |

**Microcopy notes specific to Phase 4:**
- "Reading mode" is the consistent noun across the toggle label and the
  SR announce. Never "view," "layout," "format," or "mode" alone.
- "Page" is the user-facing word for what the engine calls a "fragment."
  The word "fragment," "source range," "split," "boundary," or "block" MUST
  NOT appear in user-facing copy. The user sees "pages"; the engine sees
  fragments.
- The fallback-banner copy never says "Pretext," "calibration," "drift,"
  "DOM measurement," "atomic," "widow," or "oversize." User-facing word is
  "this part of the article" + "too large to fit on one page." Plain,
  non-alarming, agency-preserving.
- The fallback banner names the consequence ("keep reading") and the
  recovery ("switch back anytime") in plain language. It does NOT blame the
  article, the source, the corpus, or the reader.
- "Page N of M" is concise — never "You are on page N of M" or "Page N out
  of M total." The `N` and `M` are integers via `Intl.NumberFormat` with
  the user's locale; never hand-rolled.
- The keyboard-help paragraph is announced to AT, never shown visually
  (visual users see the chevron buttons and the toggle; the shortcut is a
  progressive enhancement for keyboard-first readers).

## Interaction Patterns

Phase 1+2's interaction baselines (visible focus, reduced-motion,
forced-colors, programmatic status, always-underlined links, disclosure,
skip link, settings panel, location restore, scroll-save, progress hairline,
storage failure, persistent header) carry forward unchanged and apply to
every new control. Phase 4 adds:

### 15. Mode-toggle control (D4-09, PAGE-01, A11Y-01/02/07, READ-04)

- Lives in the existing slim header (`.app-header`), inline-end side,
  **immediately inline-start of the gear button**. The header does NOT grow
  (READ-04 quiet chrome — adding chrome height would undercut the calm
  surface). The toggle is a `<button type="button" class="mode-toggle"
  aria-pressed="{bool}">` with an inline-SVG glyph.
- **Mechanism:** clicking the toggle flips `readingMode` in
  `SettingsContext` (live-apply + debounced persist — same path as every
  other settings control, D2-03). The `M` keyboard shortcut (registered
  globally on `window` when an article is mounted, see §18) calls the same
  handler.
- **Glyph state (forced-colors safety):** the SVG glyph changes between
  paginated (a single-page icon) and scrolling (a continuous-scroll icon)
  on toggle. The glyph change is the secondary cue beyond `aria-pressed`
  — it must be perceivable in forced-colors (no color-alone meaning).
- **Quiet-chrome rule (D4-09 + READ-04):** the toggle uses `--ink-soft`
  default and `--accent` ONLY when `aria-pressed="true"` (paginated active)
  — mirrors the gear-button open/closed discipline. No accent fill, no
  toolbar styling, no shadow. Min 44 × 44 px hit area.
- **On toggle (D4-10 anchor = top-of-current-view → grapheme offset →
  target):** the first visible block (scrolling) / the first block on the
  current page (paginated) is mapped to a D-05 grapheme offset, then to a
  target in the new mode. The reader stays at the same logical passage —
  they did not ask to move.
- **Focus (D4-07 subset for the toggle itself):** focus STAYS on the
  toggle after activation (predictable — the reader used the toggle). If
  the toggle was triggered via the `M` shortcut (focus was elsewhere),
  focus stays where it was (the `M` shortcut does not steal focus).
- **Live announce:** a polite live region announces *"Switched to
  paginated reading." / "Switched to scrolling reading."* immediately on
  toggle (mirrors the SectionAnnouncer pattern; never repeats on rapid
  toggles — debounced).
- **Reflow (A11Y-04):** at 320 CSS px and 200% zoom, the header MUST keep
  the wordmark, toggle, and gear visible and operable in one row. If the
  wordmark must yield, it truncates first (the controls are
  operation-critical; the wordmark is decorative).

### 16. Page-turn controls — keyboard bundle (D4-05, PAGE-02, A11Y-01/08)

- **Full keyboard bundle:** `PageUp` / `PageDown` + `ArrowLeft` /
  `ArrowRight` + `Space` (forward) / `Shift+Space` (back). Covers web
  convention (PageUp/Down), book convention (arrows), and reader
  convention (Space). Maximizes accessibility and discoverability.
- **Registered globally** on `window` when an article is mounted in
  paginated mode. Removed when the article unmounts or the mode switches to
  scrolling. Listener uses `{ passive: true }` and calls `preventDefault()`
  ONLY on the keys it actually handles (never on Space inside an input —
  the handler checks `event.target` and bails on form fields, dialogs, and
  the settings panel).
- **At page 1 / last page:** the backward / forward keys produce NO action
  (do not scroll, do not wrap, do not announce). The corresponding chevron
  button reflects `aria-disabled="true"` (see §17). The keys do not beep
  and do not steal focus.
- **Reduced motion (A11Y-06):** the page swap is **instant by default**.
  There is NO transition CSS property on the page swap (mirrors the
  ProgressHairline discipline — the global `prefers-reduced-motion` gate is
  trivially satisfied). The reader's eye moves to the new page; nothing
  slides or fades.
- **No keyboard trap (A11Y-01):** Tab cycles through the article's focusable
  elements on the current page (links, the page-side chevrons, the toggle,
  the gear, the skip link). Tab does NOT cycle through other pages' content
  — only the current page is in the tab/reading order (A11Y-03).

### 17. Page-turn controls — quiet chevron buttons (D4-06, PAGE-02, A11Y-07, READ-04)

- **Placement (researcher call — D4-06 discretion):** **page-side
  chevrons** — a Previous-page button anchored to the inline-start edge of
  the viewport, a Next-page button anchored to the inline-end edge. Both
  sit vertically centered against the page content-box (below the 48px
  header + 2px hairline). They are `position: fixed` so they stay put
  while the page content swaps.
- **Why page-side, not a bottom bar (researcher rationale):**
  - A bottom bar adds chrome height that competes with the calm page
    surface (READ-04). The slim header is already the only chrome.
  - Page-side chevrons match the book convention (turn from the edge).
  - Page-side chevrons are reachable by thumb on touch (Fitts's law —
    edges and corners are the easiest touch targets).
  - Page-side chevrons coexist with the `--measure` content box: they sit
    OUTSIDE the content-box (in the viewport margin), so they do not
    reduce the reading column width.
  - On viewports narrower than the reading measure + chevron gutter (see
    Layout §Reflow), the chevrons sit just inside the viewport edge with
    a transparent hit area and a small visible glyph so they never
    overlap text.
- **Visible glyph + invisible hit area:** the chevron is a 24 × 24 px SVG
  glyph. The hit area is the full 44 × 44 px (`--touch`) transparent
  button — the reader's pointer/touch target is generous; the visible mark
  is quiet.
- **Default state:** `--ink-soft` glyph on transparent background. No fill,
  no border, no shadow.
- **Hover / `:focus-visible`:** `--accent` glyph (matches the gear-button
  hover rule). The `:focus-visible` outline is the standard 2px solid
  `--focus-ring` + 2px offset.
- **Disabled state (page 1 / last page):** `aria-disabled="true"` + glyph
  opacity reduced to ~40% (also conveyed by `aria-disabled` so it survives
  forced-colors). The button does not fire on click; the disabled state is
  NOT conveyed by color alone.
- **No invisible click zones (D4-06):** the page content area has NO
  invisible turn-zones. Turning happens only via the chevrons, the
  keyboard bundle, or swipe (see §18). Invisible zones would conflict with
  Phase 5 text selection and are undiscoverable for the accessibility-first
  reader.
- **Touch / pointer parity (A11Y-07):** every chevron has a ≥ 44 × 44 px
  hit area. Tap = turn. Long-press does nothing (no hidden affordance).

### 18. Page-turn controls — left/right swipe (D4-06, PAGE-02, A11Y-07)

- **Swipe-vs-zoom conflict resolution (researcher call — D4-06
  discretion):**
  - **Single-touch horizontal swipe = page turn.** A `touchstart` →
    `touchend` pair where exactly one touch is active AND the horizontal
    delta exceeds the vertical delta by a clear margin (≥ 1.5× ratio) AND
    the horizontal delta exceeds a minimum threshold (~40px) registers as
    a swipe in the swipe direction (right-to-left = next page;
    left-to-right = previous page — natural book convention).
  - **Multi-touch = pinch-zoom, owned by the browser.** The handler
    bails the moment a second touch starts (`event.touches.length > 1`).
    It never calls `preventDefault()` on multi-touch sequences, so the
    browser's pinch-zoom and reflow (A11Y-04) stay native.
  - **Vertical scroll = owned by the browser.** The handler bails if the
    vertical delta exceeds the horizontal delta. Vertical pan/scroll
    inside a page that overflows its content-box (e.g. a long code block
    that didn't fragment per D4-02) stays native.
  - **`touch-action: pan-y pinch-zoom`** on the page content-box declares
    this intent to the browser so the gesture discriminator has the
    correct hint. The chevron buttons use `touch-action: manipulation`
    (no double-tap zoom delay).
- **Swipe announce:** a successful swipe fires the same "Page N of M"
  announce as a chevron tap or a keyboard turn (one announce path —
  A11Y-08 concise).
- **Reduced motion (A11Y-06):** swipe triggers the same instant page swap
  as the keyboard bundle (no slide animation).

### 19. Page-turn focus + screen-reader status (D4-07, A11Y-02/03/08)

- **Context-aware focus after a turn (D4-07):**
  - If the turn was triggered by a chevron tap or a keyboard key while
    focus was on a control (toggle, chevron, gear): focus STAYS on the
    control. The reader used the control; they expect to remain on it.
  - If the turn was triggered while focus was inside the article content
    (a link, a paragraph via SR virtual cursor): focus moves to the **top
    of the new page** — the first heading on the page, or the first
    focusable element if no heading, or the first paragraph as a
    fallback. Predictable — the reader was reading; they expect to
    resume reading.
  - The `M` shortcut and the swipe gesture do not move focus (they did
    not start from a control).
- **Single content tree (A11Y-03):** only the current page's DOM is in the
  tab/reading order. The other pages are either not rendered (preferred —
  the engine produces a single page fragment at a time) or rendered but
  `aria-hidden="true"` + `inert` if the dual-tree approach is unavoidable
  (planner's architecture call; the contract is "no duplicate active
  content tree" either way). Screen-reader reading order equals document
  order on the current page.
- **Concise SR status (A11Y-08):** on every successful turn, a polite live
  region announces *"Page {N} of {M}."* Debounced (~250ms) so rapid turns
  do not flood the live region — the announce reflects the FINAL page of a
  burst, not every intermediate. Never re-reads content; never announces
  "you turned the page"; never chatters.

### 20. "Page N of M" indicator in the hairline region (D4-08, READ-05)

- The Phase 2 progress hairline (2px tall, fixed under the 48px header)
  stays in BOTH modes. Its fill source changes:
  - **Paginated mode:** fill = `{N} / {M}` ratio (`transform: scaleX(N/M)`).
    The "N of M" indicator (Meta/Label, `--ink-soft`, 14px UI sans) sits
    centered in the hairline region (or inline-end, planner's call — the
    contract is "quiet, glanceable, low-contrast"). Updates instantly on
    every turn — no transition (mirrors the hairline discipline).
  - **Scrolling mode:** fill = scroll-ratio (unchanged from Phase 2). The
    "N of M" indicator is NOT shown in scrolling mode (there are no
    pages to count); the hairline alone carries progress.
- **The page number is informational, not identity (READ-05).** It changes
  with viewport/typography/font/asset. It is never persisted, never
  bookmarkable, never treated as a coordinate. The D-05 grapheme offset is
  the only durable passage identity (carried from Phase 1).
- **SectionAnnouncer stays in both modes** (Phase 2 D2-12). In paginated
  mode it announces the most-recently-passed heading on the current page
  (which is usually the page's first heading). It does NOT replace "Page N
  of M" — the two announces are complementary (section + position).

### 21. Mode-switch anchor (D4-10, PAGE-01, SC1)

- **Anchor = top-of-current-view → grapheme offset → target.** When the
  reader switches paginated↔scrolling:
  - In paginated→scrolling: the first block on the current page is mapped
    to its D-05 grapheme offset; scrolling mode silent-scrolls to that
    offset's DOM target (reusing Phase 2's `findScrollTarget` exactly —
    do not fork).
  - In scrolling→paginated: the first visible block (top-of-viewport) is
    mapped to its grapheme offset; paginated mode renders the page that
    CONTAINS that offset and scrolls the page-content-box so the offset's
    block is at the top.
- **Silent + instant (A11Y-06):** the anchor computation and the render
  swap are silent. No scroll animation, no fade, no slide. The reader's
  eye stays on the same passage; the surrounding chrome swaps.
- **`trustedView` retention pairing (PAGE-06):** if the mode switch
  triggers measurement (it usually does — paginated needs fresh
  fragmentation), the old mode's view stays mounted until the new
  measurement commits (Phase 3's `trustedView` contract). The reader
  never sees a blank gap.

### 22. Repagination anchor (D4-11, PAGE-05, SC4)

- **Same anchor rule as mode switch (D4-10) — one consistent passage-
  preservation principle.** When repagination commits after a
  viewport/typography/font/asset change, the grapheme offset currently at
  the TOP of the viewport stays at the top (or as close as possible) of
  the new first-visible page.
- **Pairs with PAGE-06:** the old page stays mounted during compute (Phase
  3's `trustedView` retention). The reader keeps reading the old page
  until the new page commits and anchors to the same offset. No flicker,
  no blank gap, no jump.
- **No reader action required.** The reader did not ask to move; the
  repagination is invisible. The hairline and the "N of M" indicator
  update silently when the new page commits (no announce — routine
  repagination is silent per D3-04; the `.status` region is reserved for
  consequential fallback only).
- **Reduced motion (A11Y-06):** the new page renders in place; no
  transition.

### 23. Pagination fallback (D4 fallback-area discretion, PAGE-04, PAGE-09, D3-04, D3-05)

> The PAGE-04/PAGE-09 fallback area was deferred by the user in CONTEXT.md
> with the constraints locked (D3-04 `.status` surface, D3-05 6-kind
> DiagnosticEvent shape, STACK.md "report a structured pagination failure
> reason + a usable scrolling fallback at the same passage"). The four
> open questions — fallback THRESHOLD, fallback SCOPE (per-block vs
> whole-article), banner LIFECYCLE, and which DiagnosticEvent kinds go
> reader-visible vs silent record — are researcher calls settled here.

**Fallback THRESHOLD (researcher call):**
- **Per-block oversize:** a single atomic block (D4-02 — figure, heading,
  code block, footnote reference, or unsupported disclosure) whose
  measured height exceeds **75% of the page content-box height** triggers
  fallback. (75% — not 100% — because a single block filling a whole page
  with no room for the next heading violates the calm/booklike promise;
  75% leaves room for at least a heading or a few lines of the next block
  to land with it, preserving spatial context.)
- **Non-terminating detection:** if the pagination engine produces more
  than **300 pages** for a single article revision (clearly outside the
  representative corpus's range — the longest fixture is essay-long-form),
  it aborts and falls back. (300 is a generous upper bound; the planner
  validates against the actual corpus page-count range and tightens this
  number if the corpus peak is much lower.)
- **Repeated zero-progress:** if the engine produces N consecutive pages
  that each contain zero new content (a fragmentation stall), it aborts
  and falls back. (Defensive — should never happen given D4-01/D4-02, but
  guards a future bug from producing infinite empty pages.)

**Fallback SCOPE (researcher call):** **whole-article fallback to
scrolling at the same passage.**
- Rationale: per-block scrolling region inside paginated (the alternative)
  breaks the dual-mode cleanliness (the reader would be in "paginated"
  mode but a region of the page would scroll — two navigation models in
  one view). It also complicates the keyboard model (which keys scroll
  the region vs turn the page?). STACK.md's "usable scrolling fallback at
  the same passage" reads most naturally as "switch the whole article to
  scrolling at the same passage" — exactly what the mode-toggle does
  (D4-10), just triggered automatically by the engine instead of
  manually by the reader.
- On fallback: `SettingsContext.readingMode` flips to `"scrolling"` for
  the current session (the persisted preference is NOT overwritten — the
  reader may have legitimately chosen paginated and the fallback is a
  one-time event for this article/revision). The reader lands at the
  same D-05 grapheme offset via the D4-10 anchor rule. The fallback
  banner appears. The reader can tap **Switch to pages** to retry
  paginated mode (which will fallback again if the oversize persists —
  the banner reappears).

**Banner LIFECYCLE (researcher call):**
- The banner is a non-modal, dismissible `.status` card (reuses the
  Phase 2 banner geometry — `--surface-raised` + `--hairline` border +
  4px radius + `--space-lg` padding + 14px Meta/Label heading +
  14px Meta/Label body). It sits inline at the top of `<main>`, near the
  article header. NOT sticky (READ-04 — sticky chrome competes with
  content).
- It auto-dismisses on the reader's first scroll or pointer activity
  (mirrors the ResumeBanner pattern) OR on an explicit action (**Switch
  to pages** / ×). It does NOT block reading.
- A polite live region announces *"Switched to scrolling reading."* on
  appearance (mirrors the mode-toggle announce).
- If the reader dismisses the banner and the fallback re-triggers on a
  later repagination (e.g. they enlarged the font), the banner reappears
  — it is not a one-per-session banner. (StorageBanner has different
  semantics — see 02-UI-SPEC §13; the pagination-fallback banner is a
  fresh event each time.)

**Reader-VISIBLE vs SILENT-RECORD DiagnosticEvent mapping (researcher
call — D3-05 shape locked, only the surfacing is open):**

The 6 kinds are the closed set (Phase 3). Phase 4 emits MORE of these
existing kinds (pagination failures map to `dom-fallback` or
`measurement-error`), and chooses which to surface:

| DiagnosticEvent kind | Reader-visible? | Phase 4 reasoning |
|----------------------|-----------------|-------------------|
| `dom-fallback` | **YES** (when emitted by the pagination engine for an oversize / non-terminating case) | The engine could not paginate this content; the reader is being moved to scrolling — they deserve to know why. |
| `measurement-error` | **YES** (when emitted during a pagination pass that prevents the page from committing) | Measurement failed; the page can't be trusted; the reader deserves to know why they fell back. |
| `drift-exceedance` | No (silent record) | Calibration drift is an internal health signal; the engine falls back to DOM measurement silently and pagination continues. The reader's experience is unaffected. |
| `late-epoch-drop` | No (silent record) | A stale result was dropped — this is the staleness contract WORKING AS INTENDED. Surfacing it would alarm the reader about a non-event. |
| `calibration-failure` | No (silent record) | Calibration failed at startup; the engine falls back to DOM measurement. Internal. |
| `runtime-guard-downgrade` | No (silent record) | The Pretext fast path was disabled at runtime; DOM measurement continues. Internal. |

**Reader-visible copy mapping:** the banner copy in the Copywriting table
above is the canonical surface for `dom-fallback` and `measurement-error`
when they trigger a scrolling fallback. The reader does NOT see the kind
name, the offset, the block kind, or any internal field — they see the
plain-language banner copy.

**Subscription seam:** the paginated view subscribes to
`DiagnosticBus.recent()` + `DiagnosticBus.subscribe()` (Phase 3); only
`dom-fallback` and `measurement-error` event kinds trigger the banner.
The other 4 kinds stay in the ring buffer for DEV-only diagnostic display
(planner may add a DEV-only diagnostic inspector; production never shows
them).

## Layout

Phase 1+2's visual hierarchy and breakpoints carry forward. Phase 4 adds
the paginated surface geometry, the page-turn chevron placement, and the
fallback banner geometry.

**Header + hairline + indicator stacking (top of viewport):**
1. `header.app-header` — 48px, sticky/fixed top, full width. Wordmark +
   mode-toggle + gear in one row.
2. `div.progress-hairline` — 2px, immediately under the header. In
   paginated mode, the inner fill derives from `{N}/{M}` AND the
   `.page-indicator` text ("N of M") sits centered in this region (or
   inline-end — planner's geometry call; the contract is quiet, glanceable,
   never accent-colored).
3. The page-turn chevrons anchor to the viewport edges, vertically centered
   against the page content-box (below the 50px header + hairline stack).
4. `<main id="main">` — Phase 1 inset (`padding-inline: md`, `padding-block:
   3xl`) applies to scrolling mode unchanged. In paginated mode, the inset
   is replaced by the page-content-box geometry (see Page geometry below).

**Page geometry (paginated surface, D4 page-geometry discretion):**
- `width: var(--measure)` — the same calm measure scrolling mode uses.
  Both modes share the reading column; the eye rests in the same place.
- `height: calc(100vh - 48px - 2px - 2 * var(--space-2xl))` — viewport
  minus header (48px), hairline (2px), and the top + bottom book margin
  (`2xl` = 48px each = 96px total). On a 800px-tall viewport, this leaves
  ~654px of vertical content room — enough for ~30-35 lines at default
  typography, a calm booklike page.
- `margin-inline: auto` — centered in the viewport.
- `overflow: hidden` — the page never scrolls (an oversize block triggers
  fallback per §23, never in-page scroll). Vertical overflow inside a
  `<pre>` block stays native via `overflow-x: auto` on the `<pre>` itself
  (already declared in `app.css`); horizontal pan inside a code block does
  not turn the page.
- `touch-action: pan-y pinch-zoom` — declares the gesture intent (vertical
  pan and pinch-zoom are native; horizontal swipe is ours per §18).

**Page-turn button geometry:**
- 44 × 44 px hit area (`min-height: var(--touch); min-width: var(--touch)`).
- 24 × 24 px visible glyph (inline SVG).
- Transparent background, no border (the visible mark is the glyph alone).
- Inline-start chevron anchored `position: fixed; left: var(--space-sm);
  top: calc(50% + 25px)` (vertically centered against the page content-box,
  offset by half the header+hairline stack). Inline-end chevron mirrored.
- `z-index: 5` — same layer as the hairline (above page content, below the
  header at z-index 10, below dialogs in the top layer).
- `touch-action: manipulation` — no double-tap zoom delay on tap.

**Pagination-fallback banner geometry:**
- Reuses `.status` card geometry (Phase 1) + the `.storage-banner` flex
  layout (Phase 2): `--surface-raised` background, `--hairline` border,
  4px radius, `padding: var(--space-lg)`. Flex row: main (heading + body)
  + actions (**Switch to pages** + ×) on the inline-end.
- Inline at the top of `<main>`, near the article header. NOT sticky.
- Inset matches `main#main` so the banner aligns with the article edge.

**Reflow (A11Y-04):** at 320 CSS px equivalent and 200% browser zoom:
- The header MUST keep the wordmark, mode-toggle, and gear visible in one
  row. If the wordmark must yield, it truncates first (controls are
  operation-critical).
- The page content-box MUST stay within the viewport with no horizontal
  scroll. The `--measure` cap (`max-width`) prevents overflow; if the
  viewport is narrower than the chosen measure, the content-box fills the
  available width minus `md` insets (the page becomes a single column,
  which is the calm-mobile default).
- The page-turn chevrons sit just inside the viewport edge (transparent
  hit area extends to the edge; visible glyph inset by `sm`) so they never
  overlap text.
- The hairline + "N of M" indicator MUST stay visible and unreadable-when-
  truncated (if "N of M" doesn't fit, it collapses to "N/M" — never to a
  single ambiguous number).
- All keyboard, pointer, touch, and swipe interactions MUST remain
  operable (A11Y-01, A11Y-07).

| Breakpoint | Behavior |
|-----------|----------|
| `< 640px` | Single column everywhere. Header full width with truncating wordmark. Page content-box fills width with `padding-inline: md`. Chevrons sit just inside the viewport edge. **The "N of M" indicator collapses to "N/M" if "of" doesn't fit.** Fallback banner fills width minus `md` insets. |
| `640–1024px` | Page content-box capped at the reader's chosen measure (`max-width` in `ch`), `margin-inline: auto`. Chevrons sit in the viewport margin outside the content-box. Indicator reads "N of M". Settings panel ~360–420px column over scrim (Phase 2). |
| `≥ 1024px` | Same measure cap — the reading column does NOT widen with viewport (calm measure is invariant). Chevrons have more margin room. Fixture list (Phase 1) max three columns. |

**Reduced-motion (A11Y-06, critical):** Phase 4 ships **zero required
animations.** Page turns are instant. Mode swaps are instant. Repagination
commits are instant. The defensive `@media (prefers-reduced-motion: reduce)`
block (already global in `app.css`) sets `transition: none !important;
animation: none !important; scroll-behavior: auto !important;`. Phase 4
introduces no transition/animation property on any new selector (the
page-turn chevron's `--ink-soft → --accent` hover is a color change, not
a transition — color changes are not motion). The reader with
reduced-motion preference gets the same instant, calm experience as every
other reader.
