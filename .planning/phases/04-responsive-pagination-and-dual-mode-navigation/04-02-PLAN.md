## Phase Goal

**As a** reader, **I want to** move predictably through complete responsive pages and switch or fall back to scrolling without losing my logical passage, **so that** I can read long-form content in a calm booklike way while retaining stable orientation.

This plan delivers the **two prerequisites** every later plan depends on: (1) the `readingMode` preference in `ReaderSettingsSchema` (D4-12) that the mode-aware render branch reads, and (2) the Wave 0 test infrastructure (corpus matrix enumeration + the eight pagination e2e scaffolds) that Plans 03–05 fill with real assertions.

<objective>
Add `readingMode: "paginated" | "scrolling"` to `ReaderSettingsSchema` (schemaVersion 1→2, default `"paginated"`) as a pure Zod value-shape evolution with NO Dexie store change (Pitfall 9 — the settings store is key-value; Dexie is opaque to the value shape). Existing v1 records hydrate `readingMode: "paginated"` via Zod `.default()`. Then create the Wave 0 test infrastructure the VALIDATION.md per-task map requires: the corpus × viewport × typography matrix enumeration and the eight pagination e2e spec scaffolds (each with the image-stub + IndexedDB-wipe + hash-route harness copied from tests/e2e/measurement/stale-drop.spec.ts, containing a `test.todo`/placeholder the later plans implement).

Purpose: Unblocks Plan 03 (mode-aware branch needs readingMode) and Plan 05 (corpus matrix proofs need the enumeration). No reader-facing UI in this plan — it is foundation that ships in two small, parallelizable edits.

Output: Two edited source files + one new matrix module + eight new e2e scaffolds + one extended unit test.
</objective>
