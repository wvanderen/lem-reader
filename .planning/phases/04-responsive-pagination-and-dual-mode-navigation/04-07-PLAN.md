    Returns null when no overflow (pass-through); a corrected PageFragment[] when re-fragmentation succeeded; or an empty array (length 0) when the engine emits dom-fallback.

    Algorithm (concrete):
    1. Read `fragmentEl.children` — the rendered top-level block elements of the current page (each carries data-block-index per Plan 04-06's BlockRenderer contract). These are the LIVE measured elements; their getBoundingClientRect().bottom is the truth, NOT the pre-captured LineBox[].
    2. Walk children in order; find the FIRST child whose getBoundingClientRect().bottom (relative to the fragment top) exceeds pageContentBoxHeightPx + tolerance.
    3. If no such child → return null (no overflow).
    4. Identify the offending block's article.blocks index via the data-block-index attribute. Decide by classification (classifyBlock):
       - Atomic kind (figure/heading/code-block/footnote-reference/unsupported): move the offending block AND every block after it on this page to a new page inserted at overflowingPageIndex + 1. If the offending block ALONE on a fresh page would still exceed pageContentBoxHeightPx - tolerance, emit dom-fallback via diagnostics.emit({kind:"dom-fallback", ts}) and return [].
       - Splitting kind (paragraph/bulleted-list/numbered-list/blockquote): re-read the live line boxes via readLineBoxes(childEl, blockNormalizedText(childEl), signal) (imported from src/pagination/lineBoxes.ts). Walk the resulting LineBox[] to find the largest line index `k` such that the widow-adjusted (applyLineWidowOrphan(lineBoxes, k)) before-slice bottomPx ≤ pageContentBoxHeightPx. Convert that line-box charOffset to a D-05 grapheme offset via charOffsetToGrapheme (from lineBoxes.ts). Emit a tighter PageFragment with the offending block's entry split at that grapheme offset; place the after-slice as the first entry of the new next page; move any blocks after the offending block to the new next page.
    5. Iterate: the new "next page" may itself be rendered and overflow on the NEXT post-render pass. The guard does NOT iterate synchronously (the live DOM hasn't re-rendered yet); it returns the corrected pages and lets the next post-render effect run re-check. Each correction strictly reduces the source-range covered by the overflowing page, guaranteeing termination across at most pages.length iterations.
