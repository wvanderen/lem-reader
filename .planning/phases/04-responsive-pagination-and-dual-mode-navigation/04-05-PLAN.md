## Phase Goal

**As a** reader, **I want to** move predictably through complete responsive pages and switch or fall back to scrolling without losing my logical passage, **so that** I can read long-form content in a calm booklike way while retaining stable orientation.

This plan closes the phase: it surfaces the fallback path (PAGE-04/PAGE-09 banner + session-mode flip + DiagnosticBus subscription) and proves the PAGE-03 observable invariants in real browsers across the corpus × viewport × typography matrix in Chromium, Firefox, and WebKit. After this plan all six phase requirements are met and the phase gate is green.

<objective>
Add `PaginationFallbackBanner` (non-modal `.status` card with UI-SPEC §Copywriting copy + **Switch to pages** + × dismiss + auto-dismiss on first scroll/pointer, mirroring StorageBanner/ResumeBanner geometry). Wire ArticleView to subscribe to `DiagnosticBus` — only `dom-fallback` and `measurement-error` events show the banner (the other 4 kinds stay silent record per UI-SPEC §23). On fallback, flip a SESSION-scoped mode override to scrolling at the same D-05 passage WITHOUT overwriting the persisted `readingMode` preference. Then implement the eight pagination e2e specs (scaffolded in Plan 02) with real assertions across the corpus matrix in all three Playwright engines: PAGE-01 mode-switch-anchor, PAGE-02 page-turn-controls, PAGE-03a coverage-invariant (exactly-once), PAGE-03b no-overflow-invariant, PAGE-03c termination, PAGE-04 fallback-oversize, PAGE-05 repagination-anchor, PAGE-09 fallback-banner.

Purpose: PAGE-03 (the highest-risk requirement — exactly-once/no-clipping/no-duplication/nontermination) is only provable in real browsers; this plan delivers that proof. PAGE-04 (fallback terminates with usable scrolling) + PAGE-09 (actionable diagnostic + understandable banner) close here.

Output: One new banner component + ArticleView subscription wiring + eight fully-implemented e2e specs. This plan has a human-verify checkpoint because the corpus matrix + screen-reader reading order across a turn are not fully automatable.
</objective>
