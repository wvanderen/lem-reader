<objective>
PAGE-01 M-toggle round-trip (6 failures) + PAGE-02 keyboard bundle + chevron boundary (6 failures).

Two distinct root causes, both reader/UI:

ROOT CAUSE A (PAGE-01): The M shortcut is registered on `window` by PageTurnControls ONLY when `enabled === true`, which ArticleView sets to `paginatedActive`. After the first M flips mode to scrolling, `paginatedActive` becomes false → PageTurnControls unmounts → the keydown listener is removed. The SECOND M (pressed while in scrolling mode) has no listener, so the persisted readingMode never flips back. The D4-10 anchor round-trip is the load-bearing passage-preservation behavior.

ROOT CAUSE B (PAGE-02 keyboard): After ArrowRight advances page 1→2, Space fires before React commits the state update. handleTurn reads `surfaceRef.current?.turn("next")` → commitTurn reads `currentPageIdxRef.current`. The ref is mirrored on every render (`currentPageIdxRef.current = currentPageIdx`) but between ArrowRight's setState and the next render's ref-mirror, the ref still holds the OLD value. Space's turn() reads the stale ref, advances from the OLD index, and lands on the page ArrowRight already reached. Result: Space does NOT advance.

ROOT CAUSE C (PAGE-02 chevron): At the last page, aria-disabled={isLast} = `currentPageIdx === pages.length - 1`. When the test rapidly clicks Next `total + 5` times, React batches the state updates. The DOM reflects the FINAL state only after commit. The test waits for aria-disabled="true" but the chevron's onClick → commitTurn → setCurrentPageIdx is bounded by Math.min so the final state IS the last page. The 30s timeout suggests the click is not landing — likely because `next.click().catch(() => {})` swallows a Playwright error when the button becomes aria-disabled mid-loop.

Purpose: Restore the dual-mode navigation core — M-toggle round-trip + keyboard bundle + chevron boundary reflection.
Output: M shortcut always mounted + synchronous turn path + reliable aria-disabled reflection.
</objective>

    Fix 1 (keyboard bundle Space-after-ArrowRight race): the root cause is `currentPageIdxRef.current = currentPageIdx` lags React's commit cycle. Between ArrowRight's `setCurrentPageIdx(2)` and the next render's ref-mirror, the ref still holds 1. When Space fires synchronously after ArrowRight, `commitTurn("next")` reads `currentPageIdxRef.current === 1`, computes `next = min(1+1, len-1) = 2`, calls `setCurrentPageIdx(2)` (a no-op state update), returns `moved: false` (next === cur at the ref level — actually next=2, cur=1, moved=true, but setCurrentPageIdx(2) when state is already going to 2 is a no-op). Result: page does not advance to 3.

    Concrete fix: update `currentPageIdxRef.current` SYNCHRONOUSLY inside commitTurn BEFORE calling setCurrentPageIdx. The ref becomes the source of truth for the imperative turn path; setCurrentPageIdx triggers the re-render. Pattern:

    function commitTurn(direction) {
      const p = pagesRef.current;
      if (!p || p.length === 0) return null;
      const cur = currentPageIdxRef.current;
      const next = direction === "next" ? Math.min(cur + 1, p.length - 1) : Math.max(0, cur - 1);
      const moved = next !== cur;
      if (moved) {
        currentPageIdxRef.current = next;   // SYNCHRONOUS ref update — the next turn() reads the new value
        setCurrentPageIdx(next);            // triggers re-render
      }
      return { page: next + 1, total: p.length, moved };
    }

    The same pattern applies to pagesRef if the post-render overflow guard (Plan 04-07) calls setPages — the guard must update pagesRef.current SYNCHRONOUSLY too so commitTurn sees the corrected pages on the immediate next turn.

    Fix 2 (chevron aria-disabled reflection): the bound state `isLast = currentPageIdx === pages.length - 1` (L331) reads the React state, which is correct AFTER commit. The 30s timeout in the e2e is likely because the rapid `.click().catch(() => {})` loop swallows Playwright's ActionabilityError when the button becomes aria-disabled mid-loop. Two acceptable fixes:
    - Drop the `.catch(() => {})` and let Playwright's auto-wait handle the final state. The test's existing loop is `for (let i = 0; i < total + 5; i++) await next.click().catch(() => {});` — the catch swallows real errors. BUT we cannot modify the test (the e2e is the contract). Instead: ensure the chevron button does not become literally unclickable when aria-disabled — the button stays in the DOM, stays visible, just has aria-disabled="true". Playwright's `getByRole("button", { name: "Next page" })` matches the button regardless of aria-disabled. The ActionabilityError would only fire if the button becomes invisible or detached.
    - The likely real cause: when commitTurn returns `moved: false` at the last page, setCurrentPageIdx is NOT called (correct), so React does not re-render, so the aria-disabled prop does not update from the previous render. BUT `aria-disabled={isLast}` is computed at render time from currentPageIdx — and currentPageIdx already IS the last index before the loop starts clicking past it. So aria-disabled should already be true.

(b) does the click loop hang on a specific click? Most likely fix: ensure commitTurn's synchronous ref update (Fix 1) keeps the currentPageIdx state in lockstep so the render-time aria-disabled is correct on every render.

    Also verify: the chevron onClick should NOT call preventDefault or stopPropagation when aria-disabled — the button is `aria-disabled`, NOT `disabled` (per UI-SPEC §17 — keeps it focusable). The onClick still fires; commitTurn returns moved:false; no state change; no harm. But if the test's `await next.click()` waits for the button to NOT be aria-disabled (Playwright's accessibility-actionability check), it would hang. Verify Playwright treats aria-disabled as actionable or not — if it does, the button needs `disabled`-equivalent semantics without the actual `disabled` attribute. The UI-SPEC §17 contract is `aria-disabled + opacity`, NOT `disabled` — so the button remains clickable. Playwright v1.61 should NOT treat aria-disabled as non-actionable for `click()` (only for `disabled`).
