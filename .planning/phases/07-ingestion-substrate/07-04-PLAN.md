## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Publisher HTML → Readability | Untrusted HTML crosses into the extraction engine |
| Readability output → DOMPurify | Extracted HTML crosses the sanitize boundary |
| DOMPurify output → DOM walk | Sanitized HTML crosses into the doc-model construction |
| Block tree → ArticleSchema.parse() | Constructed JSON crosses the Zod trust boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-7-15 | Tampering / XSS | mXSS via sanitizer bypass | mitigate | DOMPurify strict allowlist + USE_PROFILES html (no svg/math) + ALLOW_DATA_ATTR false + mXSS Attack Classes regression suite (this plan's Task 2 = SC#4 phase-exit gate). |
| T-7-16 | Tampering / XSS | Sanitize-then-re-introduce | mitigate | Sanitize ONCE at ingest → DOM walk → Block tree (never re-parse sanitized HTML to string then back to DOM then render). React renders Block JSON; never dangerouslySetInnerHTML (repo-wide grep gate in 07-07). |
| T-7-17 | XSS | `javascript:`/`data:` URI in surviving href/src | mitigate | DOMPurify default ALLOWED_URI_REGEXP preserved (no ALLOW_UNKNOWN_PROTOCOLS); ArticleSchema `linkableUrl`/`httpUrl` refinements fire at orchestrator parse. |
| T-7-18 | Tampering | Reverse tabnabbing (`target=_blank`) | mitigate | DOMPurify afterSanitizeAttributes hook adds `rel="noopener noreferrer"` to every surviving `<a target=_blank>`. |
| T-7-19 | Tampering | DOM clobbering (`<img id="location">`) | mitigate | htmlToBlocks maps by tag name, not by id; the Block tree carries no id attributes on inline elements; footnote IDs are regex-controlled `/^fn-\d+$/`. |
| T-7-20 | Information Disclosure | jsdom state leaks across requests in long-running Worker | mitigate | `clearWindow()` after every sanitize (isomorphic-dompurify README requirement). |
