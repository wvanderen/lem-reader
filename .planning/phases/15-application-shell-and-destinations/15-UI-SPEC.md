# Phase 15 — UI Design Contract

> Visual and interaction contract for the **application shell** (NAV-01/NAV-02,
> POLISH-07), **return-context restore** (NAV-03), and **context-gated
> controls** (NAV-05). Generated by `gsd-ui-researcher`, verified by
> `gsd-ui-checker`. Phase 15 adds one nav landmark + one link conversion to the
> existing 48px header, a route/copy rename with alias, a session-scoped
> restore module, and a token drift audit — every piece either reuses an
> existing token/pattern verbatim or extends `src/app.css` additively. Zero
> new dependencies; zero store changes.

### NEW: shell destination nav (inside `Header.tsx`)

## Interaction Contract

Phase 15 inherits the global interaction rules (READ-04 calm chrome, A11Y-06 reduced-motion gate, A11Y-07 44px touch, A11Y-05 forced-colors, global `:focus-visible` 2px ring, §Interaction 2 always-underlined links) **without modification**.

1. **Destination navigation pushes history.** Shell-nav links are plain `<a href>` — activation assigns the hash, pushing a history entry (desired Back semantics). NO `onClick` interception; middle/cmd/ctrl/shift/alt clicks fall through natively.
2. **`aria-current="page"` discipline (D15-09).** Exactly one shell-nav link carries it at all times (Library for any `list` view; Highlights for review); NEVER the brand link. Visually reinforced by weight 600 + 2px underline thickness — never color alone.
3. **Brand is the predictable home (D15-05).** `#/` literal, lands the All view — same target as the cold fallback and BackToLibrary's fallback. Keyboard/SR-reachable at ALL widths: the ≤639px collapse uses `.visually-hidden`, never `display: none` (Pitfall 9); the shell-nav e2e asserts keyboard reachability of "Lem Reader" at 320px.
4. **Alias = replaceState + direct setView (Pitfall 2).** `#/review` normalizes to `#/highlights` with NO hashchange firing — the direct router update in the same handler is load-bearing (mirror `switchLibraryView`). Never pushState.
5. **Scroll ownership (Pitfall 3).** `history.scrollRestoration = "manual"` set once early in App mount; the app's own restore is the only scroll actor on Back.
6. **Restore truthfulness (D15-11/13/14).** Filters (query + tag) restore on ALL return paths (BackToLibrary `history.back()`, shell Library link, brand). Scroll + row focus restore ONLY when the landing view matches the captured view. Degradations: row gone → h1 focus (the D14-05 default); scroll beyond list height → clamp to bottom; view mismatch → filters apply, scroll/focus reset fresh. Never restore something that isn't true.
7. **Restore timing (Pitfall 4).** Scroll + row-focus restore run only after `status === "ready"` AND rows are painted; filters initialize at first render (safe). The h1-vs-row decision happens at that same moment — one decision point, never competing effects.
8. **Scroll-then-focus ordering (Pitfall 5).** When a restorable row exists: restore `scrollTo(0, clamped)` FIRST, then focus the row link with `preventScroll: true` IF the row's bounding rect intersects the restored viewport, else focus with default scroll behavior (the row becomes visible). When no row target but view-matched: `scrollTo` alone. The h1 fallback keeps its default scroll behavior (D14-15 reset-to-top). *(Auto-resolved yolo — CONTEXT/RESEARCH left the ordering to the plan; this rule keeps the captured scroll position authoritative while never focusing an off-screen row.)*
9. **StrictMode idempotency (Pitfall 8).** Capture reads live values (`window.scrollY`, current state) so twin-mount rewrites are byte-identical; restore is idempotent; one-shot effects use previous-value comparison (the shipped `lastViewRef` pattern).
10. **Control gating (D15-15/16/18).** `[tags][annotations][mode]` render only when `articleMounted`; gear renders everywhere; nothing moves into content headers. The shell is identical in all three destinations (D15-02).
11. **320px geometry (Pitfall 1 — the phase's tightest constraint).** At 320×640 in Reader the 48px row must hold `[collapsed brand][Library|Highlights][4×44px icon buttons]` with NO wrap and NO horizontal overflow. Budget: ≤639px tuning recovers ≈68px on-token — `.app-header { padding-inline: var(--space-sm) }` (−32), `.header-controls { gap: var(--space-xs) }` (−12), `.shell-nav a { padding-inline: 0 }` (−16), `.app-header { gap: var(--space-sm) }` + `.header-start { gap: var(--space-xs) }` (−8). Sanctioned relief ladder if the e2e still measures overflow: header `padding-inline: var(--space-xs)` (−8 more). Touch targets stay 44px — padding/gap trims only. The 48px height NEVER changes. An e2e assertion at 320×640 (Reader context) that the row neither wraps nor overflows is mandatory (mirror `mobile-first-page-chrome.spec.ts`).
12. **No restore chatter (D14-09 carries).** Restore announces NOTHING via live regions — focus landing + visible state IS the communication. Zero new live regions.
13. **Reduced motion (A11Y-06).** Zero new transition/animation/scroll-behavior properties on any Phase 15 selector. `scrollTo` uses instant default behavior (the global gate forces `auto` anyway).
14. **Forced colors (A11Y-05).** Current-destination state conveyed by `aria-current` + weight/stroke; all new links get the forced underline from the existing global block; the collapsed wordmark keeps its text (system link colors apply). No color-only cues anywhere.
15. **Focus visibility.** Global `:focus-visible { outline: 2px solid var(--focus-ring); outline-offset: 2px }` applies to shell-nav links, the brand link, and the restored row link. No outline overrides.
