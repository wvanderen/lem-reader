# Phase 14 — UI Design Contract

> Visual and interaction contract for **destination truthfulness** (NAV-04) and
> **reading-state views** (LIB-07/LIB-08). Generated by `gsd-ui-researcher`,
> verified by `gsd-ui-checker`. Phase 14 is a contract layer: per-destination
> `document.title`, one uniform route-change h1-focus rule, a `<nav>` view
> switcher with counts, and per-view empty states — every piece either reuses
> an existing token/pattern verbatim or extends the authored-CSS surface in
> `src/app.css` additively. Zero new dependencies; zero store changes.

## Component Inventory

All components are **additive or behavior-wiring only**. Existing visual surfaces are reused unchanged unless flagged.

### NEW: `ViewSwitcher` (inside `LibraryView`)

- **Anatomy (D14-22):** `<nav className="view-switcher" aria-label="Library views">` containing four real links:
  `All` → `#/` · `Unread` → `#/unread` · `In progress` → `#/in-progress` · `Finished` → `#/finished`
- **Semantics:** native links (views ARE routes — D14-12); **exactly one** link carries `aria-current="page"` (the active view). NO tablist/`aria-selected` machinery.
- **Labels (sentence case — voice rule 2):** `All`, `Unread`, `In progress`, `Finished`. (The requirement's "In Progress" renders sentence-case as `In progress`, matching "Saved articles" / "Continue reading".)
- **Counts in accessible names (D14-23):** link text is `Unread (3)` — the parenthetical bare number is part of the accessible name. Counts derive from the SAME `readingState.ts` functions as membership (agreement is structural — D14-20/23/24). One item per book per view (D14-24).
- **Loading honesty:** while `status === "loading"`, links render bare labels (no `(0)` counts — zero is a lie until data resolves). Counts appear at `ready` on the existing `refreshKey` load cycle; no new invalidation machinery.
- **Placement:** first child of `section.library-section-list`, above `LibrarySearch` — the switcher governs the list; strip/add sections are view-independent (Phase 14 boundary).
- **Shared measure:** joins the centered 1100px measure (`max-width: 1100px; margin: var(--space-lg) auto 0`) alongside `.library-header`, `.library-search`, `.tag-filter`, `.library-list`.
- **CSS class `.view-switcher` (NEW):**
  - `display: flex; flex-wrap: wrap; gap: var(--space-sm)` (mirrors `.tag-filter`)
  - Each link: `display: inline-flex; align-items: center; min-height: var(--touch); padding-inline: var(--space-xs)`; `font-family: var(--font-ui); font-size: 14px; line-height: 1.45`
  - Link color/underline: global `a` rule (accent, underlined) — no color override
  - `a[aria-current="page"]`: `font-weight: 600; text-decoration-thickness: 2px` (the ONLY current-state styling)
  - `:focus-visible`: global 2px ring (inherited). Zero motion properties (reduced-motion gate trivially satisfied)

### NEW: `readingState.ts` (pure policy module — D14-20)

Not a visual component. Derives `unread | in-progress | finished` for articles AND books from existing rows; imports `FINISHED_THRESHOLD` from `ContinueReadingStrip` (never forks the 0.98 constant) and wraps `deriveBookProgress(...) === 1` for books (D14-19/D14-21). Views, counts, hairlines, the strip, `LibraryRow`, and `BookRow` all consume it. **Visual surfaces are unchanged** — only the derivation behind them unifies (the `LibraryRow` `FINISHED_RATIO` const is deleted; rendering output is byte-identical).

### NEW: `pageMeta.ts` (title helper — D14-02)

`setDocumentTitle(content)` writes `` `${truncateTitle(content)} — Lem Reader` ``. `document.title = string` is a text assignment — no injection surface (MDN/WHATWG text-only title model). `index.html`'s static `<title>Lem Reader</title>` remains the cold-load default; no restore-on-unmount (every destination, including error states, sets its own title).

- **Truncation:** content portion capped at **64 characters**; when truncated, an ellipsis `…` is appended BEFORE the ` — Lem Reader` suffix. For the EPUB chapter form, truncation applies to the combined `Chapter — Book` content portion. (Recommended 60–80 range from 14-RESEARCH §Pattern 3, locked at 64.)

### EXTENDED: `LibraryView` (view routing + per-view surfaces)

- **h1:** `<h1 tabIndex={-1}>Saved articles</h1>` — text byte-stable across ALL views (D14-25); the URL, the nav's `aria-current`, and the switcher state carry WHICH view.
- **Per-view filtering:** rows derive from `readingState.ts` over standalone articles + books (books count as ONE item — D14-24; chapters never top-level — D12-01).
- **Per-view empty states (D14-26):** when the view's membership count is 0 AND `status === "ready"` (see Copywriting below). Query/tag interplay keeps existing behavior (LIB-09/Phase 16 owns filter-within-view).
- **Focus effects:** mount-effect (warm-gated h1 focus, D14-03) + `[activeView]`-keyed effect (h1 focus on every switch, D14-15) — view switches do NOT remount LibraryView (14-RESEARCH Pitfall 3), so the switch focus MUST live in the `[activeView]` effect.
- **Title effect:** `"Saved articles — Lem Reader"`, constant across views (the URL carries the view).

### EXTENDED: `App.tsx` (router grammar + replaceState switch)

- `parseHash` gains literal view segments: `#/unread`, `#/in-progress`, `#/finished` (siblings after the `/h/` form and `#/review`); unknown `#/` segments fall back to All (D14-16 — existing fallback discipline, no new error surface).
- **View switch = `history.replaceState` + a direct router state update** (replaceState fires NO hashchange — 14-RESEARCH Pattern 2). The `<a href>` stays real for share/middle-click; `onClick` (unmodified left click only) calls `preventDefault()` + the direct switch path. Destinations keep push semantics (`window.location.hash = ...`) unchanged.
- `hasAppHistory` is NOT flipped by view switches (no hashchange fires; a view switch is not destination navigation).
- **Warm-mount flag:** a per-mount "was this mount caused by in-app navigation?" value threads to views (the `hasAppHistory` precedent — navSeq counter shape is planner's).

### EXTENDED: `ArticleView` (title + focus layering)

- **Title effect keyed `[article, chapterContext, status]`:** standalone article → `<provenance.title> — Lem Reader`; EPUB chapter → `<chapter title> — <book.title> — Lem Reader` (D14-07 — upgrades when `chapterContext` resolves); error → `Couldn't open this article — Lem Reader` (D14-06; no trailing period in titles — the h1 keeps its byte-stable period).
- **Focus layering (most-specific wins — D14-05/D14-10):** deep-link jump focus (`#/article/<id>/h/<hl>` → the `<mark>`) beats saved-location restore focus (lands at/near the restored position) beats the h1 default (fresh article, nothing to restore, warm mount). The decision lives at ONE point inside the existing effects — never a third competing effect (14-RESEARCH Pitfall 1).
- **Error state:** the existing `<h1>Couldn't open this article.</h1>` gains `tabIndex={-1}` + h1 focus parity (a truthful destination — D14-06).

### EXTENDED: `ReviewView` (title + mount focus)

- Title: `Review highlights — Lem Reader`. Mount h1 focus when warm (in-app swap only). `<h1>Review highlights</h1>` gains `tabIndex={-1}`; text byte-stable.

### REUSED unchanged (surface-stable)

- `ContinueReadingStrip` — membership refactored onto the policy module (behavior identical); surface/copy byte-unchanged (Phase 16 owns redesign).
- `LibraryRow` / `BookRow` — swap derivation to the policy module; hairline, `● Finished` mark, `Resume`, remove affordances, and all copy byte-unchanged.
- `ProgressHairline`, `BackToLibrary` (`history.back()` + `#/` fallback composes with view routes for free — the library entry already carries the replaced view URL), `Header`, `SkipLink`, `SettingsPanel`, dialogs/popovers (D14-11: overlays NEVER touch title/focus — existing trap/return discipline).

## Interaction Contract

Phase 14 inherits the global interaction rules (READ-04 calm chrome, A11Y-06 reduced-motion gate, A11Y-07 44px touch, forced-colors safety, global `:focus-visible` 2px ring) **without modification**.

1. **Route-change focus (D14-01 — the uniform rule).** Any full-content swap announces via h1 focus: the incoming view's single h1 (`tabIndex={-1}` + `.focus()`) is focused on IN-APP swaps (route change AND view switch — one mechanism, two trigger points). Focus alone announces; NO live-region chatter (D14-09).
2. **Cold loads never move focus (D14-03/D14-17).** Cold deep-links and reloads keep natural browser focus. Reload restores the view from the URL (`#/finished` stays Finished). Warm-mount detection threads from the router (planner wiring).
3. **Most-specific focus target wins (D14-05/D14-10).** In ArticleView: deep-link `#/article/<id>/h/<hl>` → the highlight `<mark>`; else a saved-location restore → at/near the restored position; else (fresh article, warm mount) → h1. One decision point inside the existing effects; never a competing third effect.
4. **Error destinations get parity (D14-06).** The error h1 is focused on in-app arrival; the error title is set — failures are truthful destinations.
5. **View switch history = replaceState (D14-13).** Destinations push; views replace. The switch handler does BOTH `history.replaceState(null, "", "#/unread")` AND the direct router state update (replaceState fires no hashchange — 14-RESEARCH Pattern 2). Unmodified left clicks only; middle/cmd/ctrl/shift/alt clicks fall through to native fragment navigation. Back from an article returns to the ORIGINATING view; the cold `#/` fallback lands on All (D14-14).
6. **`hasAppHistory` untouched by view switches** — a view switch is not destination navigation; `BackToLibrary`'s `history.back()` + `#/` fallback composes unchanged.
7. **Titles are route-scoped (D14-11).** `document.title` writes on route/view truth changes only. Overlays (SettingsPanel, drawers, dialogs, popovers) NEVER touch title or route focus — existing trap/return discipline holds; assert title stability under overlays in e2e.
8. **Switcher keyboard.** Four native links in DOM order — Tab reaches each (44px min). Enter activates (native link behavior). NO arrow-key roving, NO tablist semantics — views are routes (D14-22).
9. **`aria-current="page"`** on exactly one switcher link at all times — the AT-facing current-state signal; visually reinforced by weight 600 + 2px underline thickness (never color alone).
10. **Scroll on view switch.** `focus()` default scroll behavior delivers the reset-to-list-top (the h1 sits at content top); no separate `scrollTo` choreography. `preventScroll` is NOT used on the route-change h1 focus.
11. **Landmarks (D14-04).** One NEW nav landmark: `<nav aria-label="Library views">` (labeled because `chapter-nav aria-label="Book chapters"` already exists and Phase 15 adds an app-shell nav). Existing landmarks (`header.app-header`, `main#main`, one h1 per destination) are VERIFIED, not restructured.
12. **Reduced motion (A11Y-06).** Zero new transition/animation properties on any Phase 14 selector. View swaps and title writes are instant state changes.
13. **Forced colors (A11Y-05).** Current-view state conveyed by `aria-current` + weight/stroke (survives forced palette); counts are text; empty states are text. No color-only cues anywhere.
14. **Focus visibility.** Global `:focus-visible { outline: 2px solid var(--focus-ring); outline-offset: 2px }` applies to every switcher link. No outline overrides. The programmatically focused h1 does not show a visible ring (focus-visible is interaction-keyed) — the announcement is the SR/keyboard-orientation mechanism, consistent with W3C APG route-change practice.
15. **Agreement is structural (LIB-08).** Rows, counts, and empty states all derive from the same `readingState.ts` functions in the same render body — counts CANNOT disagree with membership. A book is ONE item in exactly one view (D14-24). Progress markers per view stay honest: Unread rows carry no hairline; In-progress rows carry partial hairlines; Finished rows carry `● Finished` (existing components, policy-driven).
