## Phase Goal (User Story)

**As a** reader who values stable, faithful content,
**I want to** open representative saved articles whose semantic structure, provenance, and logical text coordinates are explicit and verifiable,
**so that** every later reading, location, and annotation feature can trust the foundation.

This plan delivers the **curated-corpus half** of that story: the user approves 5–7 real candidate articles (D-03), the throwaway normalization script (D-09) emits canonical JSON for human review, the seed fixture is replaced with the real corpus, and Playwright + axe-core validate the full reading flow across Chromium, Firefox, and WebKit. This closes Phase 1.

## <objective>
Replace the Walking Skeleton's seed fixture with the curated 5–7 real-article corpus (D-01, D-02, D-03) and prove the four Phase 1 success criteria end-to-end: open every article with provenance (DOC-01, DOC-03), render every supported block kind in semantic order (DOC-02), disclose unsupported content inline (DOC-06), on a coordinate substrate already locked by Plan 01 (DOC-04, DOC-05). The throwaway normalization script (D-09) is the authoring aid that produces the fixtures for human review — it is not product code. Playwright (3-engine matrix) and axe-core close the validation loop.

Purpose: Phase 1's success criteria are corpus-driven. Plans 01 and 02 proved the contracts and the rendering pipeline on one seed; this plan proves them on the representative real-world articles every later phase paginates, annotates, and restores against.

Output: A curated corpus of real articles as canonical JSON, a throwaway normalization script, e2e and a11y test harnesses green across three browser engines, and Phase 1 ready for `/gsd-verify-work`.
</objective>

    - Reads a source HTML file path from `process.argv[2]`.
    - Reads the file via `node:fs/promises.readFile`.
    - Parses the HTML using a dev-only DOM walker. Use `linkedom` (install it as a dev dependency: `npm install -D linkedom`) — it is a lightweight DOM implementation suitable for server-side parsing; it is NOT a runtime dep and must NOT be imported by `src/`.
    - Walks the DOM and emits the block tree per `ArticleSchema`: headings → `heading` blocks (level from the tag name), paragraphs → `paragraph` blocks, `<ul>`/`<ol>` → `bulleted-list`/`numbered-list`, `<blockquote>` → `blockquote` (recurse into children), `<figure>` + `<figcaption>` → `figure` (alt from `<img alt>`, caption from figcaption inline text), `<pre><code>` → `code-block` (source from text content, language from class hint if present), footnote references → `footnote-reference` (id `fn-N`, marker `[N]`).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Saved source HTML → throwaway script → canonical JSON | Source HTML (untrusted, third-party) is normalized into canonical JSON; the script's output is human-reviewed before becoming a fixture |
| Canonical JSON → fixture loader → Zod parse | Each curated fixture crosses the Zod boundary at module load (fail-fast — Pitfall 8); the schema is the gate (Pitfall 4, 5 guards from Plan 01) |
| Curated fixtures → rendered DOM → axe-core | The rendered article view is audited by axe-core across three browser engines; this is the automated a11y gate (supplements, does not replace, manual passes) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-11 | Tampering (supply chain) | Throwaway normalization script (D-09) — untrusted source HTML | mitigate | Script output is human-reviewed before becoming a fixture (Task 2); fixtures re-validated through `ArticleSchema.parse` at module load; script is never imported by the app bundle (acceptance criterion grep) |
| T-01-12 | Tampering (stored XSS via fixture content) | Curated fixtures carrying attacker-controlled hrefs/srcs | mitigate | Plan 01 Zod scheme allow-list rejects non-http(s)/mailto schemes at parse time (Pitfall 5); the fixture loader fail-fasts on any malformed fixture (Pitfall 8) |
| T-01-13 | Information disclosure / Denial of service | A11y regressions in the real corpus (Pitfall 10: heading-order, list, focus) | mitigate | axe-core harness on every fixture across 3 engines (Task 3); manual keyboard + screen-reader passes documented in VALIDATION.md Manual-Only Verifications |
| T-01-14 | Tampering (DOM clobbering via real footnote ids) | Curated footnote-bearing fixtures | mitigate | Plan 01 Zod regex `/^fn-\d+$/` rejects arbitrary ids at parse time (Pitfall 4); Plan 02 renderer derives `fn-ref-N` deterministically |
| T-01-15 | Repudiation / Tampering (provenance integrity) | `provenance.originalHtmlHash` field | mitigate | Throwaway script computes SHA-256 over source HTML bytes via `node:crypto` (Task 2 acceptance criterion); the hash ties each fixture to its source revision |
