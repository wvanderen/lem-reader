# Phase 1 — UI Design Contract

> Visual and interaction contract for the Canonical Article Foundation phase.
> Generated by gsd-ui-researcher; to be verified by gsd-ui-checker.

---

## Phase Scope

Phase 1 ships two screens plus one disclosure pattern. It does NOT ship the
polished reading experience (typography controls, theme switching, calm
progress indicators, location restore — those land in Phase 2). It establishes
the **default typography and color tokens that Phase 2 will later make
user-adjustable.**

**In scope (Phase 1):**
1. Article fixture list — an index the reader uses to open an article.
2. Article view — title, metadata, source URL, and canonical semantic content
   rendered as native HTML elements (`<article>`, `<h1>`–`<h6>`, `<p>`, `<a>`,
   `<ul>`/`<ol>`, `<figure>`/`<figcaption>`, `<blockquote>`, `<pre>`/`<code>`,
   footnotes region).
3. Unsupported-content disclosure pattern (DOC-06).
4. Loading, empty, and error states for the article-open flow.
5. Default calm typography + color tokens expressed as CSS custom properties.

**Out of scope (deferred):**
- Theme switcher / light+dark pair — Phase 2 (READ-03). Phase 1 ships ONE
  default theme.
- Typography controls (family/size/spacing/measure) — Phase 2 (READ-02).
- Settings panel UI — Phase 2.
- Pagination, annotations, location restore — Phases 2, 4, 5.

**Locked by STACK.md (do not revisit):**
- Authored CSS layers + CSS custom properties (NO Tailwind, NO component
  suite, NO shadcn).
- Semantic HTML as the renderer; DOM reading order equals document order.
- React 19 + TypeScript + Vite 8 SPA; React state/context only.

**Genuinely-open decisions pre-decided as defaults (review before executor):**
- Body font family → serif stack (booklike hypothesis).
- Default palette direction → warm paper (cream/sepia) over neutral white.
- Accent hue → warm brown ink.
These three are flagged `⚠ default` below. Override before executor runs.

## Spacing Scale

All spacing MUST round to a token in this table. Multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon-to-text gap, dense list spacing, caption-to-figure gap |
| sm | 8px | Compact element spacing, list-row internal padding, metadata `<dl>` row gap |
| md | 16px | Default element spacing, paragraph-to-metadata gap, list-row vertical rhythm |
| lg | 24px | Intra-article section padding, fixture-list card internal padding |
| xl | 32px | Layout gaps, gap between article body and footnotes region |
| 2xl | 48px | Major section breaks, between title block and body |
| 3xl | 64px | Page-level top/bottom padding of reading view |
| touch | 44px | Minimum interactive hit area (fixture-list rows, source-URL link, disclosure toggle, skip link). Satisfies the operability baseline that A11Y-01 / A11Y-07 will formalize in Phase 2. |

**Exceptions (override the scale where stated):**
- **Touch target minimum: 44 × 44 px** (`touch` token above) for every interactive
  control (fixture-list rows, source-URL link, disclosure toggle, skip link).
- **Focus ring: 2px solid outline + 2px offset** (visible-focus baseline).
- **Reading measure: 64ch** (typographic, not pixel) for the article body column —
  renders roughly 640–720px depending on the resolved font. Not a spacing token.
- **Relative block rhythm** inside the article body uses `em` (not px) so Phase 2
  font-size changes preserve vertical rhythm. See Typography.

## Typography

Baseline for Phase 1. Phase 2 will make body family, body size, line height, and
spacing user-adjustable; these are the **defaults** the reader starts from.

**Font stacks** ⚠ default — review before executor:

| Role | Stack |
|------|-------|
| Body (article prose) | `'Iowan Old Style', 'Source Serif Pro', 'Source Serif 4', Georgia, Charter, 'Times New Roman', serif` |
| UI chrome (fixture list, metadata labels, controls, status text) | `system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif` |
| Code / preformatted | `ui-monospace, 'SF Mono', SFMono-Regular, Menlo, Consolas, 'Liberation Mono', monospace` |

**Type scale (exactly 4 sizes, 2 weights):**

| Role | Size | Weight | Line Height | Stack |
|------|------|--------|-------------|-------|
| Body | 18px | 400 (regular) | 1.6 | Body serif |
| Meta / Label | 14px | 400 (regular) | 1.45 | UI sans |
| Subheading (h2, h3, h4) | 22px | 600 (semibold) | 1.3 | Body serif |
| Display (article title h1) | 32px | 600 (semibold) | 1.2 | Body serif |

**Block rhythm (relative units so Phase 2 size changes preserve calm):**
- Paragraph `margin-block: 1em 1em`.
- `h2` margins: `1.5em 0.5em`; `h3`/`h4`: `1.25em 0.5em`.
- List item spacing: `0.25em`.
- Blockquote: body size, italic, `margin-inline: 1em`, `padding-inline-start: 1em`,
  left rule `2px solid var(--hairline)`.
- Code block (`<pre><code>`): 14px (Meta/Label role), weight 400, line-height 1.5,
  `padding: md`, `background: var(--surface-raised)`, `border: 1px solid var(--hairline)`,
  `border-radius: 4px`, `overflow-x: auto`. Monospace is set to the Meta/Label size so
  code blocks stay dense-readable and visually recede behind body prose, preserving the
  calm/booklike surface without introducing a fifth font size.
- Inline `<code>`: same family, `0.5em` horizontal padding, `background: var(--surface-raised)`.
- `<figcaption>`: Meta/Label role, italic, `margin-top: sm`.

**Font loading note (cross-cutting):** Phase 1 uses only web-safe system stacks,
so `document.fonts.ready` resolves immediately and there is no font-set invalidation
risk for this phase. Later phases that add web fonts MUST gate measurement on
`document.fonts.ready` per STACK.md.

## Color

Phase 1 ships ONE default theme as CSS custom properties on `:root`. Phase 2 will
introduce a `[data-theme="..."]` override without touching component CSS.

⚠ default palette direction — review before executor:

| Role | Token name | Value | Usage |
|------|-----------|-------|-------|
| Dominant (60%) | `--surface` | `#FBF8F3` | App background, article-view background |
| Secondary (30%) | `--surface-raised` | `#F2EDE3` | Fixture-list cards, metadata block, code blocks, disclosure panel |
| Ink (primary text) | `--ink` | `#1F1B16` | Body text, headings |
| Ink soft | `--ink-soft` | `#5C544A` | Metadata labels, captions, secondary chrome text |
| Accent (10%) | `--accent` | `#6B4423` | See reserved-for list below ⚠ default |
| Accent hover / active | `--accent-hover` | `#4E2F18` | Hover and active state on links and CTAs |
| Focus ring | `--focus-ring` | `#6B4423` | Visible focus outline (matches accent) |
| Destructive | `--destructive` | `#9B2C2C` | Error-state icon and border only — NO destructive actions exist in Phase 1 |
| Hairline | `--hairline` | `#D9D1C2` | Fixture-list dividers, figure borders, code-block border, blockquote rule |

**Accent reserved for (explicit list — never "all interactive elements"):**
1. Hyperlinks inside the article body.
2. The original-source URL link in the provenance block.
3. The single primary CTA affordance on each fixture-list row ("Open article").
4. The collapsed-state marker on each unsupported-content disclosure.
5. `:focus-visible` outline on every focusable element.

Accent MUST NOT be used for: body text, headings, chrome backgrounds, dividers,
captions, decorative elements, or non-link UI text.

**Contrast contract (checker validates):**
- `--ink` on `--surface`: ≥ 4.5:1 (body text).
- `--ink` on `--surface-raised`: ≥ 4.5:1.
- `--ink-soft` on `--surface`: ≥ 4.5:1.
- `--accent` on `--surface`: ≥ 4.5:1 (links count as body text).
- `--accent` on `--surface-raised`: ≥ 4.5:1.
- `--focus-ring` against any surface it appears on: ≥ 3:1 (UI component /
  large-text threshold per WCAG 2.2 SC 1.4.11).
- Forced-colors mode (`@media (forced-colors: active)`) MUST NOT remove meaning —
  links remain underlined, focus remains visible, disclosure remains operable.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Open article** (on each fixture-list row; verb + noun) |
| Fixture list page title | **Saved articles** |
| Empty state — heading | **No articles yet** |
| Empty state — body | The article set is empty. Add a curated article to the prototype corpus, then reopen this page. |
| Loading state | **Opening article…** (visible text; mirrored as the `aria-busy`/`role="status"` label) |
| Error state — open failed | **Couldn't open this article.** / The article could not be loaded. Select it again from the list, or try a different article. |
| Error state — schema invalid | **This article's data doesn't match the expected shape.** / It may be corrupted. Try a different article from the list. |
| Unsupported disclosure — collapsed summary | **Some content from the original article isn't supported yet.** |
| Unsupported disclosure — expanded body | A short list, one item per unsupported run, naming the block kind and its position in plain language (e.g. "An embedded video near the third section"). Never exposes internal IDs, source offsets, or selector jargon. |
| Article view — source label | **Originally published at** {domain} — links to original URL, opens new tab, announced as "opens in a new tab" via visually-hidden text |
| Article view — provenance block | Title (h1); author name if present; publish date if present; source-URL link |
| Skip link | **Skip to article** |
| Destructive confirmation | None — Phase 1 has no destructive actions. |

**Microcopy rules:**
- Sentences, not fragments. End with a period unless the text is a button or
  link label.
- Voice: direct, calm, second person ("you" implicit). Never "we."
- Never blame the reader. Never leak internal jargon — no "fixture," "Zod,"
  "schema," "IndexedDB," "selector," or "normalized" in user-facing copy. The
  word "fixture" is internal; user-facing copy says "article" or "saved article."
- Numbers and dates use `Intl.DateTimeFormat` with the user's locale; never
  hand-rolled date strings.

## Interaction Patterns

Behavior contracts the executor MUST honor. These are not separate components —
they are rules applied to the semantic HTML.

### 1. Opening an article
- Fixture-list rows are `<li>` containing an `<a>` (or `<button>` if no URL) with
  `aria-labelledby` pointing at the article title inside the row.
- Hit area ≥ 44 × 44 px.
- On activation, the view swaps to the article view and focus moves to the
  article `<h1>`. The `<h1>` is the first focusable element after the skip link.
- An `aria-live="polite"` status region announces "Opening article…" then
  "Loaded." or the error string.

### 2. Article links (DOC-03)
- Links inside the article body use `--accent`, are **always underlined**
  (never hover-only), and open in the same tab.
- The original-source URL link opens in a new tab with `rel="noopener noreferrer"`
  and visually-hidden text "(opens in a new tab)".

### 3. Unsupported-content disclosure (DOC-06)
- Rendered as native `<details><summary>` so it is keyboard-accessible and
  screen-reader-compatible by default.
- **Placement: inline at the exact canonical position** where the unsupported
  content was removed — never only at the top of the article. Preserves reading
  order and the canonical coordinate system Phase 1 is establishing.
- Default state: **collapsed.** The collapsed summary text is the disclosure
  copy above. The marker (disclosure triangle) uses `--accent`.
- Expanded body lists each unsupported run in plain language.
- One `<details>` per contiguous unsupported run. If multiple runs cluster
  adjacently, they may share one `<details>` with multiple list items.

### 4. Visible focus (baseline for A11Y-02)
- `:focus-visible` draws a 2px solid `--focus-ring` outline with 2px offset on
  every focusable element.
- `outline: 0` / `outline: none` is FORBIDDEN unless an equivalent visible
  replacement (e.g. box-shadow ring of equal contrast) is supplied.

### 5. Reduced motion (baseline for A11Y-06)
- Phase 1 ships **no required animations.** `<details>` reveal uses the browser
  default.
- A defensive `@media (prefers-reduced-motion: reduce)` block sets
  `transition: none; animation: none; scroll-behavior: auto;` app-wide.

### 6. Programmatic status (baseline for A11Y-08)
- Loading, success, and error states are written into a single
  `role="status" aria-live="polite" aria-atomic="true"` region.
- No focus trapping. No modal dialogs in Phase 1.

### 7. Forced colors (baseline for A11Y-05)
- `@media (forced-colors: active)` must NOT remove underlines from links, must
  NOT remove the focus outline, and must NOT hide the disclosure marker.
- Meaning is never carried by color alone (e.g. the disclosure marker is also a
  glyph; links are also underlined).

## Component Inventory (Semantic)

Phase 1 uses native HTML semantics. The "components" are:

| Region | Element | Notes |
|--------|---------|-------|
| App shell | `<div id="root">` + `<body>` styles | No persistent chrome beyond the two views |
| Skip link | `<a class="skip-link" href="#main">` | First focusable element in DOM order |
| Fixture list view | `<main id="main">` containing `<h1>Saved articles</h1>` + `<ul>` | One `<li>` per article |
| Fixture-list row | `<li><article>` | Title (`<h2>`), metadata (`<dl>` or `<p>`), source domain, "Open article" link |
| Article view | `<main id="main"><article>` | Provenance `<header>`, body, optional footnotes |
| Article header | `<header>` | `<h1>` title; `<p class="meta">` or `<dl>` for author/date; source-URL `<a>` |
| Article body | direct children of `<article>` (no extra wrapper) | `<h2>`–`<h4>`, `<p>`, `<ul>`/`<ol>`, `<blockquote>`, `<figure>`+`<figcaption>`, `<pre><code>`, inline `<code>`, `<a>` |
| Footnotes | `<section aria-label="Footnotes">` after body or `<footer>` | `<ol>`; each footnote links back to its reference via `<a href="#fn-ref-N">` |
| Unsupported disclosure | `<details><summary>` + `<ul>` in the body | Inline at canonical position; see Interaction §3 |
| Status region | `<div role="status" aria-live="polite" aria-atomic="true">` | Mirrors loading/error copy |

No custom React component library is introduced. React renders the semantic
elements above; CSS targets element selectors and a small set of class hooks
(`.skip-link`, `.meta`, `.disclosure`, `.status`).

## Layout

**Visual hierarchy:** The article body column is the primary visual anchor and the
only place the reader's eye should rest. All chrome (fixture-list cards, metadata
block, status region, disclosure markers) recedes by sitting on the 30% secondary
surface token (`--surface-raised`) and using the smaller, lower-contrast Meta/Label
typography role. The accent token is reserved exclusively for hyperlinks, the
primary CTA, the disclosure marker, and the focus ring — it never decorates chrome.

| Breakpoint | Behavior |
|-----------|----------|
| `< 640px` | Single column. Article body fills width with `padding-inline: md`. Fixture list single column. |
| `640–1024px` | Article body capped at `64ch`, `margin-inline: auto`. Fixture list two columns. |
| `≥ 1024px` | Same as 640–1024px — the reading column does NOT widen further (calm measure is invariant). Fixture list max three columns. |

Article body always uses `max-width: 64ch; margin-inline: auto;` regardless of
viewport. Calm measure is invariant across breakpoints (Phase 2 may let the
reader widen it; Phase 1 fixes it).

Reflow at 320 CSS px equivalent and 200% browser zoom MUST not lose article
content, controls, or focus visibility (baseline for A11Y-04).
