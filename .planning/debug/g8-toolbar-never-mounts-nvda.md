## Resolution

root_cause: PROTOCOL-PREMISE DEFECT (platform boundary, not a code regression). ACCEPTANCE-PROTOCOL.md v1.1 Flow C C1 documents the NVDA selection gesture as "browse-mode Shift+arrows (Firefox-native selection)" — this premise is FALSE on default NVDA configurations. Per the official NVDA User Guide (§Native Selection Mode): "By default when selecting text with the shift+arrow keys in Browse Mode, a selection is only made within NVDA's Browse Mode representation of the document, and not within the application itself." NVDA's source (virtualBuffers/gecko_ia2.py, _setSelectionOffsets) pushes the browse-mode selection to the Firefox document ONLY when Native Selection Mode is enabled (_nativeAppSelectionMode, off by default; per-document NVDA+shift+f10 toggle introduced NVDA 2024.1, persistent setting added 2026.3 also disabled by default). Therefore under the documented C1 gesture, document.getSelection() in the page NEVER becomes non-collapsed: ArticleView's selectionchange listener (src/routes/ArticleView.tsx L867-957) never reaches its valid branch, selectionRect/captureResult stay null, SelectionToolbar (which renders only when both are non-null, SelectionToolbar.tsx L176/L193-194) NEVER MOUNTS, the announce-on-appear live region (L148-156, 217-224) never fires, and at C2 the 13-11 Tab routing (L758-784, requires captureOkRef + toolbarRectActiveRef) cannot engage — Tab falls to native focus order. The tester hears NVDA speak the selected text (buffer selection) but the page is selection-blind: exactly "Toolbar is still not appearing even after NVDA+space. I never hear the 'highlight actions available'." This false premise also retroactively explains why no NVDA run (G6/G7/G8) ever observed a mounted toolbar. Page-side machinery is healthy: programmatic selections mount the toolbar in firefox (3-engine toolbar-tab-path e2e green; 13-12 shipped zero source changes). G6/G7's diagnosed mechanisms remain real but were never the C1 blocker the NVDA tester hit.
fix: NOT APPLIED (goal: find_root_cause_only). Fix directions for plan-phase --gaps: (1) PROTOCOL v1.2 (primary): Flow C C1 must instruct NVDA users to enable Native Selection Mode — NVDA+shift+f10 (NVDA ≥ 2024.1; supported in Mozilla Firefox) — BEFORE browse-mode Shift+arrows, so the document selection follows the buffer selection and the toolbar mounts; alternative/fallback gesture for older NVDA: F7 caret browsing + focus-mode Shift+arrows. Correct the false "(Firefox-native selection)" parenthetical. Keep the mount-announce cue as the confirmation signal. (2) DOCUMENT the platform boundary: with Native Selection Mode OFF (any default NVDA), NO page-side code can observe browse-mode selections — the selection exists only in NVDA's virtual buffer; the toolbar's selection-driven lifecycle is unreachable by construction. (3) RE-RUN with the corrected gesture: with native selection on, the full Flow C (mount → announce → NVDA+Space → Tab routing → containment-hold survival → Enter → highlight) should pass with ZERO code changes — that exact path is pinned green by toolbar-tab-path.spec.ts on firefox. (4) Residual to verify in the re-run: NVDA verbalization of the mount announce under browse mode (the live region follows the correct pre-exist pattern — mounts empty, text set one commit later — but has never been heard under real NVDA).
verification: Diagnosis verified by: (a) complete code read of the mount path — selectionchange (L867-957) is the ONLY toolbar-mount driver, gated solely on a non-collapsed in-article page selection, with no origin checks that could distinguish NVDA selections; all G6/G7-era machinery operates only post-mount; (b) authoritative external evidence — NVDA User Guide §Native Selection Mode verbatim ("not within the application itself... not visible on screen"), NVDA changelog 2024.1 #15830 (toggle, off by default) and 2026.3 #15908 (setting, disabled by default), NVDA source gecko_ia2.py (_setSelectionOffsets gated on _nativeAppSelectionMode with silent unsupported fallback); (c) elimination of the regression/hint-variant/announce-not-verbalized alternatives (see Eliminated — the last contradicted by the C2 outcome: a mounted toolbar + focus-mode real Tab would have routed to the Highlight button per the live-verified G7 Phase A); (d) 1:1 mapping of every clause of the tester's report onto the causal chain. Limitation: NVDA cannot be run on this macOS dev machine; the NVDA-layer facts rest on official documentation + NVDA's own source, which are authoritative. Local Playwright/firefox runs add nothing — the page-side mount path is already pinned green by existing e2e with programmatic selections, and the failing delta (buffer-only selection) exists only inside NVDA.
